# 制作单状态契约

`read_video_project` 返回 `project.workflow` 和 `workflowMode`（`initialize`、`workflow` 或 `produce`）。读取已有制作单及当前工程后，通过 `apply_video_edit` 提交一个制作单操作；它沿用现有写工具，不是新工具：

```ts
{
  projectId: string,
  requestToken: string,
  baseRevision: number,
  title: string,
  operations: [{
    type: "workflow",
    workflow: {
      stage: "initialized" | "selects" | "rough-cut" | "sound" | "captions" | "review",
      brief: string,
      outline: string,
      sources: [{
        assetId: string,
        role: "main" | "broll" | "voice" | "music" | "image" | "hold",
        note: string,
        inFrame?: number,
        outFrame?: number
      }],
      nextSteps: string[],
      blockers: string[]
    }
  }]
}
```

`projectId`、`requestToken` 和 `baseRevision` 来自刚读取的当前工程。保存此操作只更新制作单，仍会产生新的工程修订号，不改片段、音轨、字幕或原素材。后台准备完成或用户编辑后，重读工程再保存，不能沿用过期修订号。更新时给出完整制作单，保留仍有效的已有内容，不假设是局部合并。

## 字段含义与边界

| 字段                | 如何填写                                                                                        | 限制                                                                       |
| ------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `stage`             | 已到达的制作检查点，见下表                                                                      | 只使用契约列出的六个值                                                     |
| `brief`             | 用户目标、交付范围、画幅/时长/声音选择，以及简短合理假设                                        | 非空，最多 2000 字符                                                       |
| `outline`           | 拟用叙事顺序、已完成事项、审阅覆盖范围和主要取舍                                                | 非空，最多 4000 字符                                                       |
| `sources`           | 本次关键候选和需要跟进的真实来源                                                                | 最多 100 项，无候选时可为空                                                |
| `sources[].assetId` | 当前工程中的实际素材 ID                                                                         | 不使用文件路径或靠名称猜 ID                                                |
| `sources[].role`    | 主体内容 `main`、补充画面 `broll`、讲解 `voice`、音乐 `music`、图片 `image`、待审阅/暂缓 `hold` | 未审阅来源用 `hold` 并在 `note` 说明；`broll` 是内容用途，不创建叠加视频轨 |
| `sources[].note`    | 内容用途、已观察证据及源时间、取舍理由、仍未知的部分；需要时附真实任务 ID                       | 非空，最多 800 字符                                                        |
| `inFrame/outFrame`  | 已确认的源素材范围，30 fps 整数帧，采用 `[inFrame,outFrame)`                                    | 同时提供或同时省略，必须在源素材长度内且结束大于开始                       |
| `nextSteps`         | 可执行的下一步；当前批次边界、实际待完成任务和剩余来源可写在这里                                | 1–12 条，每条非空且最多 500 字符                                           |
| `blockers`          | 缺素材、实际能力缺失或未解决的任务错误；没有阻塞则 `[]`                                         | 0–12 条，每条非空且最多 500 字符                                           |

不提供范围表示尚未确定选片，不等于使用整段。`sources` 不必列出上千条素材；优先保存已确认候选和下一批重点，在 `outline` 说明整体盘点数量、已审阅范围和未审阅部分，后续按批推进。超过记录上限时不能把剩余素材默默当作已淘汰。

| `stage`       | 何时保存                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------- |
| `initialized` | 已盘点现状、选择内容路线、记录候选/待审阅来源与下一步；不表示所有素材都已精看或环境没有缺项 |
| `selects`     | 关键选片和叙事结构已有源证据，粗剪尚待执行或仍在推进                                        |
| `rough-cut`   | 当前工程已应用主要顺序与取舍，声音与细节仍待处理                                            |
| `sound`       | 原声、旁白和其他所需声音已按实际素材对齐；未需要 TTS 也可达到此阶段                         |
| `captions`    | 需要的字幕和章节包装已实际应用；用户不需要字幕时记录此选择                                  |
| `review`      | 导出前的检查已完成并记录真实待验项；接下来提交或跟踪导出任务                                |

阶段写完成事实，不能在工具失败或任务仍运行时提前标记下一阶段。后续修改影响前面的内容时可以回到对应检查点；例如用户新增一段主讲内容，需要重新选片和粗剪，而不是因为已有 `review` 就直接导出。

## 初始化和完整制作的区别

初始化模式中，一次编辑必须恰好包含一个 `workflow` 操作，且 `stage:"initialized"`。已授权的声音安装、参考提取、短试听都必须先完成或记录实际缺项；有任务排队或运行时保存会被拒绝；先等待实际任务结束，失败则记录具体阻塞，再保存。成功写入会自动结束独立初始化；**它必须是初始化的最后一步**。保存前将所有要留给下次的候选、范围和下一步写完整，不预期随后继续补写制作单。

实际缺项或已经失败的准备可以写入 `blockers` 后完成初始化，交付“制作单已保存，缺项已列明”，不能宣称环境已全部就绪。不重复提交没有新依据的失败任务，也不调用不存在的结束工具。Agent 没有保存制作单就结束，且没有后台任务可继续等待时，初始化会显示失败；用聊天里的计划替代持久保存不算完成。

完整制作模式保存 `initialized` 后继续选片和制作，不停在计划。`video-init` 不把本次任务转为独立初始化；以 `workflowMode` 和当前用户请求为准，由 `video-workflow` 接着执行。

## 恢复与成片状态

恢复时先比对真实工程和任务：制作单记有粗剪但工程片段已被用户改过，应复查变化；记有等待任务则查该实际任务，不能直接重新提交。任务 ID 可写在 `outline`、相关来源的 `note` 或 `nextSteps` 中，不新增 `jobIds`、`checkpoint`、`completed` 等未经支持字段。

导出前保存 `review` 和具体下一步，例如“导出当前内容并检查字幕换行、句尾完整性；无法在 Agent 中实际播放的听感留在交付说明”。再重新读取最新修订号，提交导出并跟踪结果。成功与否由真实持久导出任务判断，制作单没有 `done` 或 `exported` 阶段；不为了标记完成在导出成功后再次修改工程修订号。仅静态检查不能报告已连续观看或试听成片。

初始化声音配置随自动请求保存，不增加 workflow 字段。安装成功、独立参考资产、短试听资产与待试听确认分别写在 outline/sources/nextSteps，缺录音或逐字稿写 blockers。初始化声音仅通过 setup_video_tts、extract_video_reference、prepare_video_voice 完成；后者最多 120 字且不会入轨。
