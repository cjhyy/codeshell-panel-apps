# 从素材到成片

用户明确要求“先根据素材写文案、剪草稿和配字幕，我觉得 OK 后再自己录音”时，通过 `Skill` 加载 `video-studio:narration-workflow`，将本次执行交给它：先保存可审阅草稿并等待用户确认，后续以用户选定的真实录音继续制作。此时不执行下面的连续成片流程，不用 TTS 代替本人声音。单纯要求“这堆素材做一版”或已有口播需要剪好，仍按下面流程推进；不把分阶段确认强加给其他完整制作请求。

通过 `Skill` 显式加载 `video-studio:video-init`，按其正文初始化或恢复当前制作单；再加载 `video-studio:video-production` 获取共享工具与时间规则，依据用户目标执行到可播放的成片。具体调用字段以 Panel 工具 schema 为准，不要求读取额外文件。所有写工具的工程身份、请求令牌和修订号来自当前读取，不通过 shell 或外部脚本绕过面板能力。

用户已经要求完整制作时，预处理、保存制作单、应用剪辑和本地导出直接推进。非关键偏好采用合理假设，保持可修改；只有用户明确要求先看方案时停在提案审阅。初始化不重置工程，续做不从头重剪。

## 选择内容路线

根据真实素材和交付目标选择路线，不把“统一删停顿、加 TTS、加字幕、配音乐”用于所有素材：

| 用户请求示例                                         | 实际制作路线                                                                                                                                                                                          |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| “素材和想法先做成文案、剪一版，我觉得 OK 再自己口播” | 交给 `narration-workflow`：保存可编辑文案、草稿和明确的临时字幕→用户按钮确认并自行录音→真实转写和原声整理→依实际声音重排画面、替换字幕→导出。不能在草稿阶段自动越过确认，也不能用估计时长硬裁新录音。 |
| “二十多条出游视频和照片，剪一分钟竖屏”               | 代表性画面初筛→深入候选动作→到达/体验/收尾的事件顺序。保留有意义现场声，照片补叙事间隙；没有对白不全量转写，不按文件名假定拍摄先后，不平均分配所有素材。                                              |
| “十分钟口播压到两分钟，去嗯啊和重说，保留我的声音”   | 真实文稿挑完整论点→粗剪内容→按词级时间/静音候选精剪→需要时增强原声。保留呼吸与限定语，不生成替代 TTS；润色的新句仅作为补录稿，不能声称原录音已改字。                                                  |
| “录屏加讲解，做新手能跟着操作的教程”                 | 明确结果→前提/关键步骤/结果检查；把讲解与实际操作帧对应，再删无用等待。独立录音无同步依据就记录缺项，不猜对齐；检查字幕不遮挡操作，标题卡只服务章节。                                                 |
| “采访长视频有三个重点，先做一个成片”                 | 读回答前后文→选本次一个主题→保留完整观点与条件→再精剪停顿。其余主题记入后续计划，不擅自导出多个作品；多机位不代表已自动同步。                                                                         |
| “产品演示和照片，三十秒介绍，配中文讲解”             | 核实实拍能力→真实演示建立开场→有限关键点与收尾→稳定文案后生成实际 TTS→按语音时长编画面。事实不补造，末句不硬裁，声音从真实目录选。                                                                    |
| “接着昨天工程做，今天补拍了三段”                     | 读取制作单/工程/任务→只准备新增来源→核实补拍解决的缺项→局部插入→重算受影响字幕和音轨。保留已有剪辑与成功产物；相同内容已有成功导出就复用，运行中任务继续跟踪。                                        |

当前画面是单路磁吸序列，另有独立音轨。补充画面作为序列中的片段使用，可承接独立讲解音轨；不能据此声称有多层视频叠加、画中画或自动主体跟踪。

## 推进制作单

1. **选片与结构。** 复用初始化的源时间证据，补看尚未确认的候选范围；确定开场、展开和结束。已有剪辑优先保留与目标一致的部分。原声、独立录音或旁白决定主线时先固定主要表达；不为追求时长截掉关键条件和结论。将已确认的选片和下一步写入制作单。
2. **粗剪。** 先安排完整叙事顺序和大范围入出点，再处理重复与节奏。重读工程并通过 `apply_video_edit` 分批应用；每批最多 100 项，新增/切分 ID 等返回真实工程后再使用。重排、裁剪和删除会影响声音与字幕，遵循已加载的 `video-production` 正文时间规则；不清空已有序列重新添加一遍。保存粗剪检查点与已完成事项。
3. **声音。** 优先保留可用原声，按需要做响度均衡或降噪；处理结果是完整源音频，使用时匹配原片 `inFrame/outFrame/startFrame` 并静音重复原声。讲解确实缺失、或用户要求合成旁白时再用 TTS；用户已经指定安装引擎时调用 `video-studio:tts-setup`。本人克隆可用目录中的 Audio8（audio8-tts）或 Qwen3-TTS，复用已验证的用户参考与配方；若只选了粗剪区间，先 extract_video_reference 提取实际音频，再 prepare_video_voice 短试听。初始化阶段的试听不直接充当整段旁白，完整旁白需另用 create_video_voiceover。等待真实音频完成，以实际时长修订画面，使用 `audio-add` 入轨，保留句尾。文案润色先保存文字，改字不等于原录音已经改变；未经用户要求不把其声音替换成机器声音。音乐仅使用现有可用来源，是否保留现场声按内容决定。
4. **字幕与包装。** 粗剪和声音时序稳定后，从真实源转写映射到最终序列，再添加字幕；只有句级时间就用句级字幕，不伪造逐词高亮时点。保留用户已有字幕 ID，修改文字有语义依据。选择实际支持的 `classic`、`bold` 或 `minimal` 字幕样式。章节卡和解释场景只在结构需要时生成，等待真实素材入库后加入序列。标题和数据有来源，不用装饰制造不存在的事实。
5. **精修。** 检查主线完整、关键内容仍在、动作/语句没有被错误截断、画幅和字幕可读、音轨正确对齐、无重复原声。可用工具只返回静态帧或分析元数据时，说明尚待实际试听或连续观看的部分，不声称已听过未播放的声音。保留现有工程与源素材，记录具体修改结果。
6. **导出和验收。** 先保存 `review` 检查点和具体待验项，再重读当前工程与修订号，确认素材可访问和音轨/字幕未越界，调用 `render_video_project`。跟踪返回的真实任务至 `succeeded` 并读取有效视频结果；排队成功不是成片完成。以持久导出任务关联成片，不为标记完成再改工程。交付真实结果与简要制作说明。若当前面板没有导出或实际播放能力，如实区分已完成的编辑、已生成的视频和仍待用户播放验收的事项。

## 中断、恢复和返工

每次恢复先读工程、制作单和相关任务。已经成功的预处理、语音、场景、剪辑和同版本导出直接复用；仍在运行的任务继续跟踪，不再提交一份。某个来源失效或用户改了剪辑时，重算受影响的候选、字幕和音轨，保留其他已完成工作；不能只替换旧操作的 `baseRevision` 再重放。

用 `video-init` 正文给出的 `workflow` 操作保存完整制作单，阶段依次反映实际已完成的 `initialized/selects/rough-cut/sound/captions/review`，受影响阶段可回退。保留 `brief/outline/sources/nextSteps/blockers` 的有效内容；检查点描述已发生的事实，计划中的工作不能标为完成。写入失败时保留实际任务 ID 并报告保存失败，不假装进度已经持久化。

同一失败没有新依据时停止重复提交，报告具体阶段与仍可用的工程。只有缺少用户必需素材或不具备的能力才留下明确阻塞；不能为了每个小偏好反复中断已授权的完整流程。
