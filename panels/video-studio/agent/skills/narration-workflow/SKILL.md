# 先做草稿，再录自己的声音

用 `Panel` 工具完成。通过 `Skill` 显式加载 `video-studio:video-production` 获取专门协调器工具及其 30 fps 兼容投影时间规则；需要整理素材时加载 `video-studio:video-init`。以实际 Panel schema 为准，不要求读取引用文件，不通过 shell 或外部脚本制作。被加载技能的通用“继续导出”要求不改变本技能当前阶段的范围。

用户给出的目标、文字和已导入素材共同决定内容。将实际观察到的画面、真实原声文稿和用户说明区分开；文件名不能证明画面内容，用户提供的表达要点也不代表画面已经拍到。非关键偏好采用合理默认值；已有工程和用户修改保留，缺失镜头写明具体缺项。

这个流程使用 `read_video_project.workflowMode` 的 `draft` 和 `narration` 两种模式。每次先读当前 `project`、`requestToken`、`revision` 和 `project.narration`，按面板实际启动的模式执行。所有写入都使用当前身份、令牌与修订号；旧工程或用户修改后的旧操作不能直接重放。

`project.narration` 的 `phase` 为 `draft/review/approved/recorded/aligned`，`captionBasis` 为 `draft/recording`，还包含 `draftCaptionIds` 和可选的 `approvedScript/approvedFingerprint/alignmentFingerprint/recordingAssetId`。这些字段由面板协调层维护，不是 Agent 可写操作。确认文案和剪辑、选择录音、授予设备权限均由用户在面板操作；Agent 不开启设备、不代替用户确认、不复制或伪造批准快照。

完整新版多轨内容通过 `read_video_project({editor:{view:"project"}})` 读取，不能用旧投影重建。通用 v2 编辑不能跳过本流程确认/录音选择；修改批准依赖会退回 review 并保留原确认追溯。

## draft：把文字和素材变成可审阅的草稿

1. **确定主线和材料。** 结合用户输入、制作单和素材决定开场、展开、收尾。用真实关键帧、源文稿及分析数据审阅候选，按需预处理；纯画面不必全量转写。记录真实源时间和可观察内容，不声称从少数静态帧理解了整段动作。素材很多时先初筛再深入候选，未审阅范围明确保留。
2. **写适合本人说出的文案。** 按用户要表达的意思写短句、自然衔接、明确指代，保留事实、语气和必要条件。让每段承担一个叙事作用，并能对应现有可用画面。通过 `set_video_script` 携带 `finish:false` 保存可编辑文稿（保存后面板会按文稿生成估时的临时字幕），不能只在聊天里贴一篇，也不能在画面和字幕尚未完成时提前结束。用户没提供的产品效果、经历和数据不补造；画面不足时调整表达或记录待补内容，不默认安排额外拍摄。
3. **制作可编辑的草稿。** 根据段落安排现有素材的真实源范围，通过 `apply_video_edit` 建立或局部调整序列；实拍、多轨或 `legacyView.timelineComplete=false` 的工程用 editor 分支并附本次 grant。先让画面顺序和表达成立，再估计口播所需停留；估时用于草稿节奏，不是最终声音长度。保留用户已有合理剪辑，不为套用新方案清空重建。现场声按叙事需要保留或调低；此阶段不调用 TTS、不生成替代本人声音的临时配音。
4. **配明确的临时字幕。** 保存文稿时，面板已按意思分句，在当前序列画面时长内按序列帧率估时生成临时字幕，并记入 `draftCaptionIds`；后续改稿只替换这个集合。画面调整后如需重排，可重新保存文稿，或用 editor 分支 `captions` 的 `text` 改字、`add` 补充（带本次 grant 添加的字幕会记为临时字幕）；旧格式 `caption` 操作仍可用，新增 ID 以 `draft-narration-` 开头。不根据时间或相似文字猜测现有标题的归属。临时字幕来自文字稿的估时，随草稿状态明确标记为待录音对齐；不能称作真实转写、逐词同步或已完成音画同步。保留用户独立标题和字幕，不盲目删除全部文字。
5. **保存并停在审阅。** 确认已有非空文稿、真实画面序列和临时口播字幕，且本次后台任务均已结束。最后重读工程，通过 `apply_video_edit` 保存完整的 `workflow` 操作并设 `stage:"review"`；制作单格式采用 `video-init` 正文契约，写明草稿已做部分及等待用户确认/录音。此调用会把 `phase` 设为 `review` 并结束本次任务。告诉用户能编辑文案、预览画面和字幕，确认后再录口播；指出具体待补内容。这里的完成是“草稿可审阅”，禁止调用 `render_video_project`、自动开始录制或把流程推进为已确认。

草稿需要返工时，按用户反馈改动相应文案、选片或字幕并重新提交审阅。用户点击确认按钮后，面板才保存批准快照并将文稿填入提词器；这不会自动申请设备权限或开始录制。文案和结构后来改变会使旧批准失效，预处理本身增加修订号不等于用户改稿；以面板的批准有效性判断为准。

## narration：按确认稿和本人录音完成视频

1. **核实本次来源。** 只有用户已确认草稿、绑定本次录音后，点击后续对齐按钮才进入 `narration` 模式。读取 `approvedScript`、批准有效性和 `recordingAssetId`；来源可为纯录音或带声音的视频，只使用真实存在且可访问的指定素材。没选定录音或确认已失效时，保留工程并返回面板所需的具体用户操作；不自行从其他音轨猜一段声音。本阶段不调用 `set_video_script` 改确认稿，不调用 TTS。
2. **识别实际说了什么。** 复用成功预处理，否则对 `recordingAssetId` 请求 `prepare_video_assets` 并设置 `transcribe:true`，等待成功后分页读取完整真实转写。对照确认稿识别漏说、增补、改口、重录和意思变化。口语措辞不同而意思一致可据实安排；数字、否定、事实、观点或结论改变，以及漏掉必要限定语、改变论证因果时，停止后续对齐完成与导出，列明具体差异及影响，让用户回面板审阅修改后重新确认。用完整 `workflow` 且 `stage:"review"` 保存具体 `blockers`，协调层会回到待确认阶段并停止任务，不生成正式字幕或导出；这不等于用户已经确认。识别不清楚的词也应标明，不猜造说过的话。
3. **保留本人的声音。** 保留真实转写覆盖的所有说话内容、呼吸余量和句尾；可以依据真实静音证据裁掉无对白首尾或调整长停顿，不能为贴合草稿删除整句。明显重说需要用户先在口播编辑中决定取舍，不擅自删掉有转写的内容以通过时长限制。只有句级时间时不精切句中单词。需要补录时指出具体句子，不自动假设补录时长与旧片段相同；新录音仍须重新选择和真实转写。
4. **按声音重排画面。** 以指定录音实际长度安排画面，先确保画面可容纳整段录音，再放入录音：旧格式调用 `audio-add`，明确给出 `assetId:recordingAssetId`、`inFrame:0` 和 `outFrame:该素材实际 durationFrames` 以及合法 `startFrame`，不省略出点让默认值截短声音；实拍或多轨工程用 editor 分支（附本次 grant）在音频轨加入完整录音片段。面板把这些编排记为录音进度；改写确认稿、改变画幅或替换录音素材的编辑会被拒绝。若按真实静音证据拆分，所有有声文稿范围仍须保留，并留呼吸余量。画面不够长时优先调整或补用现有合适镜头、图片或实际可生成的必要场景；不能用 `min(录音长度,草稿长度)` 硬裁掉结尾，也不为填满草稿任意拉伸声音。所有音轨都应落在实际画面范围内。画面重排会连动音轨和字幕，按共享时间规则分批编辑、重读，再核实真实映射。保留现场声的片段避免重复混入同一份人声。
5. **提交真实对齐。** 画面和实际口播音轨准备好、转写成功且无待处理任务后，重读工程，用 `apply_video_edit` 保存完整 `workflow`，设置 `stage:"review"`。协调层会检查指定录音的真实转写、每段说话是否被实际音轨保留，再删除 `draftCaptionIds` 集合中的临时字幕，将转写按实际音轨源范围映射为字幕；成功后状态才是 `phase:"aligned"`、`captionBasis:"recording"`。不要手写一批估计的“正式字幕”来绕过此步骤。
6. **核对结果后真实导出。** 重新读取确认 `aligned` 和 `recording`，检查整段声音未截尾、字幕内容来自实录且不越界、音量和原声关系合理。字幕映射依据是：协调层按录音在音频轨上实际发声的源范围（包括变速、嵌套序列和多个实例）以精确时间映射转写，字幕绑定到对应录音片段，之后随录音移动；同源多实例分别生成。保留独立标题和其他用户文字。通过检查后调用 `render_video_project`。收到 `accepted/operationId/preparing` 只表示已受理准备；用 `read_video_project({view:"jobs",jobIds:[operationId]})` 查询 `operations`，取得真实 `jobId` 后跟踪 `jobs` 至 `succeeded`，交付有效视频结果。重复同一已授权请求会复用回执；准备失败或重开后 `interrupted` 时先核查已有任务，不重交相同请求，也不能重新写入或伪造原审批。没有实际播放能力时如实说明连续观看/试听仍需用户验收，不把元数据检查描述为已经听过成片。

转写或导出失败时保存实际任务和仍可用的工程，只在修正了输入或有明确可重试依据后重试。恢复时先复用成功来源、已保存确认和仍在运行的任务，不从头生成一份，也不跨工程应用旧录音或旧批准。
