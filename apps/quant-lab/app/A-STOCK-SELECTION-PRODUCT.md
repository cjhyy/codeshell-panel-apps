# Sequoia A 股选股工作台：产品设计 v1

> 状态：v0.29.0 已实现核心主流程、首页分区、实时板块下钻、独立研究优先股、个股公司研究报告、顶层长期关注页、可核验的行情更新状态、可选择并锁定来源的本地历史基础库，以及双线/KDJ/量能/价格形态四维证据层；不代表实时荐股结果
> 核心原则：给方向，但不伪造确定性；先板块、后个股；允许当天没有候选。

## 1. 产品定位

Sequoia 不是“又一个指标大全”，而是一套每天可以重复使用的 A 股研究流程。首页同时提供两条线：

- **系统发现**：每天主动给出当前值得优先研究的主题、板块和板块内候选；
- **我的关注**：长期跟踪用户收藏的板块和个股，提示状态变化与入场/退出核验时机。

系统发现流程：

1. 判断今天的市场环境是否适合选股；
2. 给出最多 3 个优先研究板块；
3. 跨优先板块先给最多 5 只研究优先股；每个板块再列最多 3 只代表股，并分出等待买点与最多 2 只时机确认；
4. 解释为什么只是代表股、尚缺什么条件、为什么确认、什么情况下作废；
5. 将观察对象加入关注，随后用 T+5 / T+20 结果校准方法。

首页第一屏必须直接回答：

- 今天该不该选股；
- 今天先看哪些板块；
- 板块里先研究哪些股票；
- 下一步要核验什么。

产品默认面向“暂时没有明确方向”的用户，同时照顾已经有长期研究方向的用户。条件选股器、龙虎榜和异动扫描是二级工具，不再与首页主流程争夺注意力。

## 2. 当前问题诊断

现有投资工作台有市场脉搏、龙虎榜、成交异动、候选扫描、指数诊断和事件雷达，但这些入口优先级相同，用户需要自己拼接结论。

具体断点：

- 市场脉搏能显示板块强弱，但不能直接进入该板块的个股候选；
- 候选扫描主要按技术和流动性从全市场排序，缺少“为什么是今天、为什么属于当前主线”；
- 候选列表缺少板块阶段、反方证据、失效条件和待核验信息；
- 页面没有“今天不选”的合法结果，容易为了给结果而强行给股票；
- 高级工具太早暴露，初次使用者不知道先点什么。

## 3. 每日主流程

```text
数据新鲜度检查
      ↓
市场环境闸门 ── 弱势/退潮 ──→ 今日不勉强选股，只列观察条件
      ↓ 强势/轮动
板块持续性排序（最多 3 个）
      ↓
板块代表股（强弱与流动性，不等于可买）
      ↓
等待买点（列出未满足条件）
      ↓
完整收盘时机确认（每板块最多 2 只，可以为 0）
      ↓
证据核验：支持 / 反对 / 缺失 / 失效条件
      ↓
加入观察清单 → T+5 / T+20 复盘
```

用户不需要先配置公式。首页只保留一个主要动作：`生成今日选股`。

## 4. 首页信息架构

### 4.1 顶部：今日选股

- 数据时间：行情、板块、新闻分别显示更新时间；
- 当前策略：默认“趋势 + 板块持续性”；
- 主要按钮：生成今日选股；
- 次要入口：历史表现、规则说明、更多研究工具。

### 4.2 市场环境闸门

只输出四种状态：

| 状态 | 产品行为 |
| --- | --- |
| 强势 | 最多 3 个板块、6 只候选 |
| 轮动 | 最多 3 个板块、4 只候选，要求板块证据更强 |
| 弱势 | 最多 1 个板块、2 只观察候选，不给“进入核验”状态 |
| 退潮 | 可以返回 0 只，列出等待条件 |

同时显示判断依据：市场宽度、主要指数趋势、涨跌停结构、成交额变化。若关键数据过期，停止生成并明确提示。

### 4.3 今日优先研究板块

最多 3 个板块。每个板块必须显示：

- 生命周期：萌芽 / 扩散 / 主升 / 拥挤 / 退潮；
- 1 日、5 日、20 日相对强度；
- 板块宽度：上涨家数、站上 20 日线比例；
- 量能确认；
- 新闻或公告催化及其时间；
- 一条支持理由和一条主要风险；
- `查看板块候选`动作。

板块不能仅凭单日涨幅入选。没有持续性或缺少可核验催化时，应降级为“异动观察”。

### 4.4 板块内三层选股漏斗

板块代表股、等待买点和时机确认必须分区展示。代表股不能因为排名靠前自动进入时机确认；盘中信号不能进入收盘确认。确认区每板块最多 2 只，整页最多 6 只，并允许为 0。卡片包含：

- 股票名称、代码、所属板块；
- 状态：进入核验 / 观察 / 排除；
- 当日板块内相对排名，不显示虚假的“上涨概率”；
- 三条支持证据；
- 两条反方证据或风险；
- 尚未核验的数据；
- 明确失效条件；
- 数据截止时间；
- 动作：加入观察、展开证据、排除。

候选股票的文案使用“研究候选”，不使用“买入”“稳赚”“目标价”。

### 4.5 为什么没有选其他股票

默认折叠，展开后按原因汇总：

- ST / 退市风险；
- 停牌或成交数据异常；
- 流动性不足；
- 接近涨停，追高风险；
- 个股趋势弱于板块；
- 基本面或公告数据缺失；
- 板块已进入拥挤或退潮阶段。

这部分用于建立信任，也方便定位筛选器是否过严。

### 4.6 历史校准

首页底部只显示方法表现，不展示夸张胜率：

- 最近 20 个交易日生成过多少候选；
- T+5 / T+20 相对沪深 300 和所属板块的中位数超额；
- 最大不利波动；
- 0 候选日数量；
- 不同市场状态下的分组表现。

所有历史统计必须使用当时可获得的数据，避免未来函数和幸存者偏差。

### 4.7 我的长期关注

首页在系统推荐之后显示“我的关注”摘要，不用用户在两个完全隔离的页面间来回切换。

用户可以添加：

- 主题或行业板块；
- A 股个股；
- 自己的关注理由、预计观察周期和需要核验的问题。

每个关注对象只显示一种当前状态：

| 状态 | 含义 | 产品动作 |
| --- | --- | --- |
| 等待 | 长期逻辑未破坏，但没有合适量价时机 | 继续跟踪，不提醒操作 |
| 机会核验 | 趋势、相对强度与量价同时改善 | 提醒打开证据页核验 |
| 持有跟踪 | 用户记录已建仓，核心条件仍有效 | 跟踪失效条件，不重复催促 |
| 风险升高 | 板块宽度、个股趋势或催化出现恶化 | 提醒检查减仓/退出规则 |
| 已失效 | 用户预设的核心逻辑或价格条件被破坏 | 从活跃机会中移出，进入复盘 |

“系统发现”和“我的关注”使用相同的证据结构，区别只是来源：前者由系统全市场排序产生，后者由用户自选研究池触发。

### 4.8 入场与退出时机

产品可以给时机，但必须给“条件成立”而不是一句主观的“可以买了”。默认采用两层确认：先看板块，再看个股。

板块入场核验默认要求：

- 60 日趋势向上或完成修复；
- 20 日相对沪深 300 强度转正并持续改善；
- 板块宽度改善，不是少数权重股单独拉升；
- 突破时有量能确认，或回踩关键趋势后重新转强；
- 最新产业、政策或盈利证据没有推翻原研究逻辑；
- 拥挤和追高过滤没有触发。

个股入场核验默认要求：

- 所属板块处于扩散或主升阶段；
- 个股趋势完整，且相对板块强度改善；
- 流动性、停牌、ST、涨跌停可成交性检查通过；
- 出现可解释的突破、回踩确认或趋势恢复形态；
- 财务、估值和公告信息没有重大冲突；
- 页面已经给出明确失效条件。

退出或风险提示由以下事件触发：

- 个股跌破用户预设趋势条件且未快速修复；
- 个股连续弱于所属板块；
- 板块宽度显著收缩并进入退潮；
- 原有产业、业绩或公告逻辑被新事实推翻；
- 拥挤、波动或不可成交风险快速上升；
- 达到用户预设的持有周期、风险预算或复盘日期。

这些阈值必须支持用户调整，并用历史快照校准。未完成样本外验证前，状态只能命名为“机会核验”或“风险升高”，不能包装成确定性买卖指令。

## 5. 评分与硬规则

评分只用于同一天、同一板块内排序，不解释为收益概率。

### 5.1 数据闸门

任一关键条件失败时，不进入评分：

- A 股正常交易标的；
- 排除 ST、`*ST`、退市整理和长期停牌；
- 行情、复权和成交额数据完整；
- 达到最低成交额与自由流通市值要求；
- 不是仅靠一字板或无法成交的形态；
- 板块归属和板块行情可用；
- 页面展示的行情与新闻时间未过期。

### 5.2 板块分数

| 维度 | 权重 | 说明 |
| --- | ---: | --- |
| 5 / 20 日相对强度 | 30% | 相对宽基指数，不用单日涨幅替代 |
| 板块宽度 | 20% | 上涨覆盖率与站上趋势线比例 |
| 量能确认 | 20% | 成交额变化及量价匹配 |
| 持续性 | 15% | 多日排名稳定度，抑制一日游 |
| 可核验催化 | 10% | 政策、产业、公司事件及时间 |
| 拥挤惩罚 | -5% | 高位加速、涨停集中、情绪过热 |

如果催化缺失，不直接判错，但必须显示“驱动未核验”，且不能标记为最高信心。

### 5.3 个股分数

| 维度 | 权重 | 说明 |
| --- | ---: | --- |
| 20 / 60 日趋势 | 25% | 复权价格趋势结构 |
| 相对板块强度 | 20% | 个股是否真正强于所属板块 |
| 量价确认 | 15% | 突破、回踩和量能是否匹配 |
| 流动性 | 15% | 成交额、冲击成本代理指标 |
| 波动与追高风险 | 10% | 高波动、跳空、接近涨停惩罚 |
| 基本面与估值证据 | 15% | 财务、估值、公告；缺失时明确降级 |

第一阶段若基本面和估值数据尚未接入，输出必须命名为“技术候选”，不能命名为“核心推荐”。

## 6. 候选证据对象

每只候选应生成结构化记录，页面不依赖一段不可审计的 AI 文案：

```json
{
  "asOf": "交易日与时间",
  "marketRegime": "rotation",
  "sector": {
    "name": "示例板块",
    "stage": "expansion",
    "rank": 1,
    "evidence": [],
    "risks": []
  },
  "stock": {
    "symbol": "60XXXX",
    "name": "示例股票",
    "rankInSector": 1,
    "status": "verify",
    "supportingEvidence": [],
    "opposingEvidence": [],
    "missingEvidence": [],
    "invalidatesWhen": [],
    "sourceTimestamps": {}
  }
}
```

AI 只负责解释结构化结果、关联新闻和提示冲突；价格、均线、排名、阈值和回测全部由确定性代码计算。

## 7. 三个使用模式

首页默认只突出第一个模式：

1. **今天看什么**：没有方向时，从市场到主题、板块再到个股；
2. **我的长期关注**：持续跟踪收藏的板块和个股，等待状态变化；
3. **我看好一个板块**：选择板块，查看板块阶段和板块内候选；
4. **我已经有股票**：对单股做证据核验和失效条件检查。

基金不混入股票榜单。后续基金页可以复用相同思路：先资产 / 风格环境，再选基金类别，再按暴露、费用、回撤和基金经理稳定性筛选。

## 8. 异常与空状态

- **数据过期**：不沿用旧榜单冒充今日结果；显示最后更新时间和缺失源；
- **没有合格板块**：显示“今日没有持续性主线”，并列出重新进入的条件；
- **有板块、无合格个股**：保留板块观察，不强行跨板块凑数；
- **新闻与价格冲突**：同时展示，不让 AI 自动覆盖量价事实；
- **基本面缺失**：候选降级，并明确“尚未完成基本面核验”；
- **数据源失败**：按来源降级，不把部分结果包装成完整结论。

## 9. 版本路线图

### P0：把首页做对

- 将首页改为“市场环境 → 3 个板块 → 6 只候选 → 证据核验”；
- 在同一首页增加“我的关注”摘要，支持收藏板块和个股；
- 为关注对象增加等待 / 机会核验 / 持有跟踪 / 风险升高 / 已失效状态；
- 市场脉搏中的板块可以直接驱动候选扫描；
- 增加板块归属、板块历史和板块内相对强度；
- 增加 0 候选结果与排除原因；
- 将龙虎榜、异动、指数诊断和事件雷达移入“更多研究工具”。

### P1：把证据补齐

- 接入财务、估值、公告和新闻时间线；
- 每只候选显示支持、反对、缺失和失效条件；
- 建立每日候选快照和 T+5 / T+20 结果页；
- 增加“我看好一个板块”和“我已经有股票”两个入口。

### P2：把方法校准

- 建立 point-in-time 股票池，纳入退市股和历史成分；
- 处理复权、停牌、涨跌停和不可成交情况；
- 采用滚动训练 / 样本外评估，并与宽基和板块比较；
- 校准不同市场环境下的阈值；
- 再考虑 Qlib 等重型量化框架，避免过早引入复杂度。

## 10. P0 验收标准

- 新用户进入首页 10 秒内能说出“今天是否适合选、先看哪三个板块、第一只候选为什么入选”；
- 首页最多一个主按钮、三个板块、六只候选；
- 每只候选至少有 3 条支持证据、1 条风险、1 个失效条件和数据时间；
- 板块和个股可追溯到原始确定性指标；
- 弱势或数据不足时可以返回 0 只；
- 不出现无法证明的上涨概率、目标价和确定性买卖建议；
- 历史表现与生成时快照绑定，不使用未来数据。

## 11. 可借鉴产品与开源项目

### A 股产品

- [通达信](https://help.tdx.com.cn/function.html)：条件公式、盘中预警和区间统计成熟，适合参考“规则透明 + 提醒”；
- [东方财富](https://emdesk.eastmoney.com/pc_activity/Pages/VIPTrade/pages/answer.html)：条件选股、板块、资讯和公告连接紧密，适合参考“数据广度 + 信息下钻”；
- [同花顺 i问财](https://www.iwencai.com/)：自然语言输入门槛低，适合放在二级的“问一句”入口；
- 不直接复制它们把大量条件并列展示的首页结构。

### GitHub

- [`zhaobu/investment-skills`](https://github.com/zhaobu/investment-skills)：值得借鉴“市场状态 → 热点持续性 → 拥挤检查 → 板块 → 个股 → 排除”的流程；
- [`97Gz/StockNova`](https://github.com/97Gz/StockNova)：值得借鉴“代码计算、AI 解读”和历史日期截断验证；
- [`guiwzh/stock`](https://github.com/guiwzh/stock)：值得借鉴价值、技术、估值分层，但其 README 也提醒幸存者偏差与复权问题；
- [`Dzy-HW-XD/a-share-quant-selector`](https://github.com/Dzy-HW-XD/a-share-quant-selector)：借鉴双线位置、KDJ、量能结构、价格形态和异常量风险的四维解释；不使用其少量人工成功案例直接生成“相似度荐股”，四维形态只作为现有板块内研究排序的一个证据层；
- [`prince121212/Ashare`](https://github.com/prince121212/Ashare)：可借鉴每日短名单与历史切换，不直接采用未经独立回测的策略分数；
- [`akfamily/akshare`](https://github.com/akfamily/akshare)：适合作为研究数据层参考，不是现成选股产品；
- [`microsoft/qlib`](https://github.com/microsoft/qlib)：适合后续量化研究与样本外评估，不适合作为 P0 首页体验的起点；
- [`vnpy/vnpy`](https://github.com/vnpy/vnpy)：强项是专业交易和执行，不是当前选股工作台的核心层；
- [`rainx/pytdx`](https://github.com/rainx/pytdx) 已归档，不作为新系统的数据基础。

## 12. 明确不做

- 不用多个 AI 角色投票制造“专业感”；
- 不展示无法校准的 80 分、90 分或上涨概率；
- 不把新闻热度直接当成买入信号；
- 不因页面需要内容而每天强行推荐；
- P0 不做自动交易，不接券商下单；
- P0 不把股票、基金、港股和美股塞进同一个榜单。
