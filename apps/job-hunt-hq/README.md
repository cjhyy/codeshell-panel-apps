# Job Hunt HQ · 求职作战室

一个只绑定 **CodeShell 当前项目与当前 Session** 的求职可视化面板。聊天仍在
CodeShell Session 中进行；面板包自带 `job-hunt-workflow` Skill 和结构化工具。你把工作经历、
项目说明、代码和规则放进当前项目，Agent 会在相关对话中自动识别这个 Skill，读取根目录的
`CODESHELL.md`，再生成并展示岗位、完整 JD、公司调研、通用或定制简历、补强计划、面试题和真实复盘。

## 当前能力

- 在首页选择零个、一个或多个岗位，再自由组合本次需要的任务
- 用“简历优化、面试准备、面试复盘、完整岗位包”预设快速勾选，但仍可继续增减任务
- 手动粘贴 BOSS 直聘、LinkedIn、拉勾、猎聘、脉脉、前程无忧、智联招聘、公司官网等渠道的职位 JD
- 选择多个招聘渠道，让当前 Agent 逐站搜索公开职位并把统一格式的结果写回机会面板
- 按规范化链接或“渠道 + 公司 + 职位 + 地点”自动去重，并保留原始来源
- 自动读取当前项目中的 `CODESHELL.md` 与已验证资料，不要求手动添加其他 Repo
- 在当前 CodeShell Session 中直接聊天，不在面板里建立第二套聊天记录
- 一个项目开关同时控制面板、`job-hunt-workflow` Skill 和面板工具
- 把 Agent 识别出的个人定位、项目证据与工作经历作为只读上下文展示
- 查看公司官网、招聘官网、公开评价、面试流程、来源和核验风险
- 查看每个岗位的完整 JD，并从当前项目资料生成 Markdown 粗版简历
- 让 Agent 基于当前 JD 继续补强，并把新草稿写回面板
- 根据 JD、工作经历与当前项目代码生成技术、项目、系统设计、行为和能力差距题
- 每道题展示出题原因、证据来源、回答要点和可能追问
- 让 Agent 按已保存题单逐题模拟面试，并在回答后给出证据与表达反馈
- 对照 JD 与真实经历区分已有优势、能力缺口和证据缺口，保存按优先级排序的补强计划
- 把真实面试问题、回答、反馈和结果写回面板，再按用户勾选的任务迭代简历、题库或准备计划
- Agent 每次写回时同步更新当前项目根目录的 `job-hunt-panel.json`
- 在浏览器中使用示例预览数据；安装进 CodeShell 后按项目隔离真实数据

## 当前项目工作方式

1. 在 CodeShell 的扩展设置中，只为要使用的当前项目开启 Job Hunt HQ。
2. 把简历原始资料、工作经历、项目说明和代码放在这个项目里。
3. 在项目根目录的 `CODESHELL.md` 写清楚资料位置、事实边界、目标岗位和优化规则。
4. 在首页选择需要处理的岗位和任务，发送到当前 Session；也可以直接说“找岗位”“调研当前公司”
   “根据 JD 生成简历”“准备面试题”或“复盘刚才的面试”。Agent 会自动加载面板自带 Skill，
   并把结果写回面板。
5. 面板自动读取根目录的 `job-hunt-panel.json`，展示岗位、完整 JD、公司调研、Resume、
   补强计划、面试题和复盘。

不需要在面板中选择或打开其他 Repo。切换到另一个 CodeShell 项目时，只有那个项目自己的开关和数据会生效。

## 安装

在 CodeShell 中打开 **扩展 → Panel Apps → 选择源码文件夹**，选择本目录并完成权限审查。
安装后只为当前求职项目开启它，再从右侧面板的 `+` 菜单打开。项目开关关闭后，这个面板、
它的结构化工具和 `job-hunt-hq:job-hunt-workflow` Skill 会一起从该项目的 Session 中消失。

开发修改后，在 Panel Apps 管理页点击 **从源码更新** 即可加载新版本。

## 设计边界

Panel App 自身不绕过任何招聘网站的登录、验证码、robots、访问频率或其他限制。公开 JD
搜索由当前 Agent 使用其可用浏览能力逐站完成；某个渠道受限时会跳过并说明原因，也可回到面板手动粘贴 JD。

## 添加新的招聘渠道

招聘渠道通过 `app/app.js` 中的 `JOB_PROVIDERS` 注册表管理。新增渠道只需要补充稳定 ID、显示名称和公开域名提示；职位仍写入统一的
company、title、location、salary、source、source_id、url、published_at、employment_type、description
和 match 字段。面板不包含站点专用爬虫，避免某个网站改版拖垮整个产品。
