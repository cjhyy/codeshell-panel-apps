# Job Hunt HQ · 求职作战室

3.0 的持续重构方案见 [TECHNICAL-PLAN-v3.md](app/TECHNICAL-PLAN-v3.md)。它以当前项目为唯一
业务数据源，并把面试训练收敛为“直接练习、立即反馈、针对性重练”，同时保留 Base Resume、
JD Variant 与逐项证据审核。

一个只绑定 **CodeShell 当前项目与当前 Session** 的求职可视化面板。通用协作仍在
CodeShell Session 中进行；模拟面试则全程留在面板中逐题作答和语音转写，保存时直接写进当前项目，不发送 Session 消息，也不等待 Agent。需要时再单独让 Agent 读取某一道已保存回答进行复盘评分。面板包自带工作流编排、岗位情报、简历写作、简历设计和面试教练五个 Skill，以及结构化工具。你把工作经历、
项目说明、代码和规则放进当前项目，Agent 会在相关对话中自动识别适用 Skill，读取根目录的
`CODESHELL.md`，先建立方向级 Base Resume，再生成并展示岗位、完整 JD、公司调研、JD 定制版简历、
补强计划、面试题和真实复盘。

## v2 信息架构

### 简历不再是一张会被反复覆盖的草稿

v2 把简历拆成四个有来源关系的层级：

1. **事实与证据**：工作经历、项目、Repo、Commit 和候选人本人确认；JD 只能说明招聘方要什么，不能证明候选人做过什么。
2. **方向级 Base Resume**：一个岗位大类一份稳定母版，保留完整职业叙事和逐条 Source，不绑定具体公司。
3. **JD Variant**：从一个明确的 Base 派生，只改变重点、顺序和真实关键词覆盖，不改写历史事实。
4. **Application File**：从一个确切版本导出的公开 PDF。内部 QA、证据账本和 Source 注释不会进入公开文件；版本编辑时间晚于 PDF 时，面板会把导出标记为过期。

“当前决策”每次只给一个最有价值的下一步：补资料、建 Base、回答私有事实 QA、修 Source、选择目标 JD、生成或打开岗位版、重新导出。它不会因为历史上某个无关版本导出过 PDF，就把当前版本误判为已完成。

PDF 新鲜度按真实时间比较，而不是依赖数组顺序或 ISO 字符串排序。修改正文、模板、密度或全局照片都会使受影响版本的旧 PDF 明确显示“已过期”；无法解析时间的旧记录也不会被误判为最新。

保存到项目和导出 PDF 共用同一个发布门槛：姓名、职位定位和联系方式必须可用；每条公开要点必须有重点说明、Source 的具体证据内容、至少一个可练追问，并明确标记为“已核验”；`needs_review` 只允许保留为内部草稿。标点、空白、全半角或大小写微调不会让原有证据映射失效，但实质改写必须重新核验。草稿、Base 与岗位版可以在门槛前持续编辑和派生，但未核验版本不能被误当成最终投递文件。候选人姓名、联系方式或画像变化时，所有受影响版本的旧 PDF 也会一起过期。

私有事实 QA 优先绑定经历与项目动作，不拿孤立的技能词硬问。候选人可直接暂不回答或重新打开；已回答内容只进入内部证据，必须再次明确触发简历优化才会影响公开正文。项目快照会严格校验版本关系、视觉设置、PDF 导出、逐条 Source 和 QA 状态。

### 面试内容分成四类对象

- **长期题库（Canonical Question Bank）**：一题一份规范记录，维护题型、能力、难度、优先级、状态、来源、标签、回答骨架、参考回答、追问、个人笔记和练习历史；可直接筛出已练题和最近低于 70 分的待加强题。
- **练习题单（Practice Set）**：围绕一个 JD、2–8 个相似 JD、Commit 或混合目标临时选题。多个题单可以引用同一道长期题，不复制练习历史。
- **模拟面试场次（Mock Session）**：一次面板逐题作答事件，独立记录已保存回答和可选的已评分题、场次状态、优势、优先改进和下一步。它不是 CodeShell Session；中断后可以继续，也可以由用户明确标记停止。
- **真实面试复盘（Real Debrief）**：只保存用户实际经历的面试问题、回答、反馈与结果；永远不把模拟训练冒充为真实招聘进展。

旧版 `interviewSets[].questions` 会在读取时自动迁移到长期题库；题干过短或缺少分类、评估能力、Source 的旧“可练习”题会安全退回“待整理”。题单本地 ID 不会被误当成全局 ID；题干先执行 NFKC、大小写、空白、标点与符号归一化，再用双哈希指纹去重。重复题会合并 Source、岗位、题单引用和练习记录。完成整理后，用户直接编辑过的题干、分类、能力标签、答案、笔记、状态与掌握度是权威记录，旧题单、旧手工副本或之后的 Agent 生成结果都不能覆盖回来；真实面试复盘仍可追加新的真实来源与回答素材。改写题干时旧指纹会作为历史别名保留，以后再次出现旧措辞也不会产生重复题。

“从当前 Session 整理”只读取当前任务中实际出现的面试题，排除回答、元对话和 Agent 澄清问句。`session:current` 会在写入时固化为本次 Trace 或 Session 的稳定 Source，后续仍能区分是哪次整理。新题先进入“待整理”；题干、分类、评估能力与 Source 齐全后，用户才能确认转成“可练习”，不会未经审阅自动污染长期题库。整套模拟与单题练习都只选择“可练习”或“已掌握”的规范题，“待整理”与“已归档”题会自动跳过。

真实面试复盘仍是独立招聘事件，但其中实际被问到的问题会自动去重进入“待整理”题库，并保留 `real-interview:<debrief-id>` 来源。它只补充真实来源、回答要点和复盘信息，不会把已有的手工措辞、已掌握状态或练习历史降级。复盘最多保留 80 场；达到上限会明确要求先备份和清理，不会为了保存新记录而静默丢掉最早一场。

模拟面试的逐题评分必须绑定同一个场次 ID，并且只能写入本场已经确认可练习的题目；完成场次后不能继续追加评分，也不能覆盖终态总结。本场题目数、平均分和四维分都由面板从逐题记录确定性计算并保存快照；即使题目后来归档淘汰，或单题只保留最近 20 次练习，旧场次仍显示当时的完整进度与成绩。最多保留 80 场时优先淘汰已结束历史；若 80 场都未结束，会先提示结束一场，不会丢掉可恢复进度。

项目快照最多保留 600 道规范题和 20 个练习题单，每个题单最多 30 道；600 的上限覆盖旧版 20 × 30 道题的最坏迁移情况。达到容量时只会自动淘汰已归档题；有效题不会被静默覆盖，新增或导入会提示先归档。新题单轮换时优先保留仍有未结束模拟的旧题单；如果 20 套题单都被进行中场次占用，就先提示结束一场，而不是把可恢复的模拟变成悬空记录。题库、题单和历史模拟场次在迁移时会修复局部 ID，并移除无法解析的题目引用；历史成绩快照仍会保留。

600 题最坏迁移会超过 CodeShell 单个项目文本文件的 384 KiB 写入上限，因此 v2 会按实际 UTF-8 字节数自动分片；每个根索引和分片都保留安全余量。分片缺失、代际不一致或写入冲突会把项目标记为不可读并停止覆盖，而不是截断题目、答案或练习历史。极端数据若需要超过 128 个安全分片，会明确要求先归档过量历史，不会写出一个下次无法读取的根索引。

## 当前项目工作方式

1. 在 CodeShell 的扩展设置中，只为要使用的当前项目开启 Job Hunt HQ。
2. 打开“材料库 / 当前项目上下文”，点击“初始化当前项目”。Agent 会优先识别已经存在的简历、工作经历、项目说明和代码；缺少资料归属时才创建 `career-data/` 模板。
3. 初始化会创建或补充根目录的 `CODESHELL.md`，写清资料位置、事实边界、目标岗位和优化规则；已有项目指令不会被覆盖。
4. 在“渠道管理”中一次连接一个渠道：先验证，确实需要登录时再点“登录并保存”，CodeShell 会保存 Cookie、恢复到当前任务并自动验证。搜索弹窗只允许搜索本 Session 已验证通过的所选渠道。微信文字、截图、PDF、Word、猎头/朋友转发和项目文件先进入 `career-data/jd/inbox/`；完整内容进入岗位池，残缺内容进入待补全线索。
5. 需要持续补充岗位时，在“渠道管理 → 定时补充完整 JD”选择频率、时间和目标数量。任务绑定当前求职项目与当前 Session，登录失效时会跳过对应渠道而不是后台等待；每次运行会在 `career-data/discovery/runs/` 留下可恢复的结果收据。
6. 先进入“简历版本”，填写目标大类并点击“生成 / 更新 Base”，确认基础内容后，再选择岗位并点击
   “基于当前 JD 定制”。也可以在首页选择需要处理的岗位和任务，发送到当前 Session；或直接说
   “找岗位”“先做前端 Base Resume”“根据 JD 生成定制版”“准备面试题”或“复盘刚才的面试”。Agent 会自动加载面板自带 Skill，
   并把结果写回面板。
7. 查看任意岗位、简历、题目或复盘时，点击卡片上的“问 Agent”即可把对象 ID 和你的指令发送到
   当前 Session，不需要复制粘贴内容，也不会新建第二套聊天。
8. 面板自动读取根目录的 `job-hunt-panel.json`，展示岗位、完整 JD、公司调研、Resume、
   补强计划、面试题和复盘。

不需要在面板中选择或打开其他 Repo。切换到另一个 CodeShell 项目时，只有那个项目自己的开关和数据会生效。

## 安装

在 CodeShell 中打开 **扩展 → Panel Apps → 选择源码文件夹**，选择本目录并完成权限审查。
安装后只为当前求职项目开启它，再从右侧面板的 `+` 菜单打开。项目开关关闭后，这个面板、
它的结构化工具以及五个 `job-hunt-hq:*` Skills 会一起从该项目的 Session 中消失。

开发修改后，在 Panel Apps 管理页点击 **从源码更新** 即可加载新版本。

## 设计边界

Panel App 自身不绕过任何招聘网站的登录、验证码、robots、访问频率或其他限制。公开 JD
搜索由当前 Agent 使用当前 Session 的浏览器逐站完成；需要登录或验证码时会把页面交给用户，用户完成后继续。暂时无法登录时会保存其他渠道的透明部分结果，也可回到面板手动粘贴 JD。

## 添加新的招聘渠道

招聘渠道通过 `app/app.js` 中的 `JOB_PROVIDERS` 注册表管理。新增渠道只需要补充稳定 ID、显示名称和公开域名提示；职位仍写入统一的
company、title、location、salary、source、source_id、url、published_at、employment_type、description
和 match 字段。面板不包含站点专用爬虫，避免某个网站改版拖垮整个产品。

## 待发布：项目草稿隔离与恢复

简历正文和面试回答的浏览器应急副本通过项目 Host 存储中的持久随机标识区分归属，
不再共享全局草稿，也不只用目录路径区分云端项目。多窗口通过条件写入取得同一标识，
各窗口分别保留浏览器副本；Host 草稿保存使用读取到的版本，冲突停止覆盖，保存回执
丢失只读取核对而不直接重发。读取失败不当作空数据，编辑区域会停止修改，可下载
备份并明确重新读取。切换项目会取消旧保存计时器，限制快照分片、重试及延迟响应
只作用于原项目。旧项目未确认的输入仍保留备份；切回时可从该项目副本恢复。

顶部“下载草稿备份”包含当前输入、页面内旧项目草稿、当前项目各窗口原始浏览器
记录和旧版未标明项目的记录。旧版全局副本不自动归入当前项目，也不被删除。
“恢复草稿备份”读取本格式或旧版草稿 JSON（最多 8 MB），先展示来源记录与正文，
再明确确认恢复到当前项目。简历正文创建新版本，清除不再适用的 PDF 和证据关联；
面试回答必须选择当前项目的题目，不沿用旧练习编号，也不直接提交答案。恢复前的
内容保存在独立浏览器归档，归档不会触发自动恢复；当前简历仍进入项目版本历史。
先条件保存恢复草稿，再写项目文件，文件写入失败会保留待同步草稿；恢复策略会随
缓存保存，重开后不会重新带回旧正文的证据关联。项目或内容变化、并发冲突、取消
均不会继续应用原审阅结果。没有自动归属迁移；浏览器副本只在该浏览器保留，跨设备恢复
依赖已成功保存的 Host 项目数据。旧 Host 缺少条件存储能力时保持原 Host 缓存，
明确提示无并发保护并停用浏览器自动恢复。损坏浏览器副本可在明确重新读取时逐字节归档，不删除原记录；以后只跳过已归档的同一份坏内容，其他窗口改过的记录仍重新检查。其他业务控制器和真实模型／设备流程
仍需分别验收，不能由本组草稿测试推定完成。

实际 Host 存储验证：
`node scripts/job-hunt-host-draft-storage.mjs <已构建的 server 包目录>`。
该检查只创建和清理自己的临时数据，验证磁盘存储、并发、同路径不同 Host、重启
和权限撤销，不代替目标服务器或真实账号验收。
