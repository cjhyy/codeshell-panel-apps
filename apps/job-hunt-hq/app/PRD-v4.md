# Job Hunt HQ v4 PRD：从“功能集合”重构为“求职任务工作台”

> 状态：Draft for implementation<br>
> 产品版本：v4.0<br>
> 文档范围：信息架构、页面职责、核心流程和验收标准
> 不包含：视觉稿、数据模型重写、招聘渠道抓取策略、AI Prompt 细节

## 1. 背景

Job Hunt HQ 已经具备岗位收集、JD 管理、公司情报、简历版本、证据审核、长期题库、模拟面试、语音回答、评分、真实面试复盘和 Agent Trace 等完整能力。

当前主要问题不再是“缺功能”，而是功能持续叠加后，页面同时承载了过多不同层级的任务：

- 顶层导航有 6 个业务页面，侧栏还常驻 7 个岗位阶段筛选。
- “岗位池”同时展示项目初始化、JD 来源说明、JD 收件箱、统计、岗位列表、JD 阅读和 Agent 任务编排。
- “面试训练”同时展示今日练习、可用性检查、能力分析、题单生成、题单列表、逐题作答、补强计划、真实复盘和模拟历史。
- “简历版本”同时展示流程进度、当前决策、正文编辑、视觉设置、证据、事实 QA、版本库和导出。
- 渠道、公司情报、简历和面试被设计为并列模块，但用户真实思路通常是“围绕一个岗位继续准备”。
- 解释性文案大量常驻，导致真正要点击的操作反而不突出。

因此，v4 不以增加功能为目标，而是重新定义每个页面只帮助用户完成一个可识别的任务。

## 2. 产品判断

### 2.1 核心用户

当前版本服务一个主要角色：正在持续求职、需要维护多份 JD、简历和面试记录的个人候选人。

这个用户既会进行低频的资料维护，也会进行高频的日常操作：

- 今天应该先做什么；
- 哪个岗位值得继续投入；
- 当前简历能不能投；
- 现在练哪一道题；
- 上次回答哪里需要改进。

### 2.2 核心产品承诺

用户打开面板后，不需要理解内部数据结构、Agent Trace 或生成链路，就能立即知道：

1. 当前最值得做的一件事；
2. 完成它需要进入哪个对象；
3. 操作是否已经保存到当前项目；
4. 下一步是什么。

### 2.3 设计依据

v4 采用以下原则：

- 从“一页一个主要任务”开始，页面只保留完成当前任务必要的信息。
- 按用户目标组织，而不是按内部模块、数据表或 Agent 能力组织。
- 说明只在决策点出现；低频详情使用抽屉、弹窗或折叠区渐进展示。
- 专业工作台可以使用列表 + 详情等高密度结构，但不能同时出现多个相互竞争的主操作。

参考：

- [GOV.UK：Start with one thing per page](https://www.gov.uk/service-manual/design/form-structure)
- [GOV.UK：Do one task per transaction](https://www.gov.uk/service-manual/design/scoping-your-service)
- [GOV.UK：Writing for user interfaces](https://www.gov.uk/service-manual/design/writing-for-user-interfaces)

## 3. 目标与非目标

### 3.1 目标

1. 顶层导航从 6 个业务入口和常驻阶段筛选，收敛为 5 个稳定入口。
2. 每个页面首屏只出现 1 个主操作，最多 2 个次操作。
3. 用户进入页面后，5 秒内能判断该页面是做什么的、当前状态是什么、下一步点哪里。
4. 将“对象内容”“操作流程”“系统运行状态”分层，不再同屏竞争。
5. 面试训练默认直接开练，不先要求理解题单、题库、健康度和生成来源。
6. 简历默认围绕当前版本编辑和投递，不先展示完整版本库与证据账本。
7. 保留现有项目数据和历史记录，不要求迁移业务 schema 才能完成页面重构。

### 3.2 非目标

- 不删除长期题库、公司情报、渠道验证、版本历史或 Trace 能力。
- 不把模拟面试重新迁回 CodeShell Session。
- 不恢复“从 Commit 深挖”入口。
- 不改变项目文件作为权威数据源的原则。
- 不在 v4 首版增加新的岗位抓取渠道或简历模板。
- 不用隐藏功能的方式制造“简洁”；所有低频能力必须仍然可发现。

## 4. v4 信息架构

```text
今日
├── 当前最优先行动
├── 今日待办
└── 最近变化

岗位
├── 机会
├── JD 收件箱
├── 获取岗位
└── 岗位详情
    ├── JD
    ├── 公司情报
    ├── 准备材料
    └── 投递进展

简历
├── 当前版本
├── 版本关系
├── 投递文件
└── 按需抽屉：证据 / 事实 QA / 样式

面试
├── 练习
├── 题库
└── 记录
    ├── 模拟场次
    ├── 能力趋势
    └── 真实面试复盘

数据
├── 个人档案
├── 经历与项目
└── 文件与同步

全局活动抽屉
├── Agent 执行
├── Trace
└── 保存、冲突与错误状态
```

### 4.1 顶层导航

| 新入口 | 用户问题 | 旧内容去向 |
| --- | --- | --- |
| 今日 | 我现在最该做什么？ | 新增轻量首页，不放完整业务列表 |
| 岗位 | 哪些岗位值得投入？这个岗位下一步是什么？ | 原岗位池 + JD 收件箱 + 渠道管理 + 公司情报 |
| 简历 | 当前简历是否可投？应该编辑哪个版本？ | 原简历版本页和简历工作区 |
| 面试 | 我现在练什么？上次练得怎么样？ | 原面试训练 + 题库 + 场次 + 复盘 |
| 数据 | 我的事实资料是否完整可信？ | 原数据源页 |

以下内容不再占用顶层导航：

- “渠道管理”进入“岗位 → 获取岗位”。
- “公司情报”进入具体岗位详情。
- 岗位阶段筛选进入岗位页工具栏，不再常驻整个侧栏。
- “Session / Trace”改为右上角活动入口，不和业务主操作并列。

## 5. 全局框架

### 5.1 顶栏

顶栏只保留：

- 当前项目名称与同步状态；
- 全局搜索；
- “＋ 添加”菜单：导入 JD、手工加题、记录真实面试；
- 活动入口：进行中数量、失败提醒和 Trace。

“找岗位”和“导入 JD”不再在所有页面常驻为两个大按钮，它们只在岗位上下文中成为主操作。

### 5.2 侧栏

侧栏只显示 5 个顶层入口和必要数量提示。

禁止在侧栏继续展示：

- 全部机会、待筛选、感兴趣、准备中、已投递、面试、Offer、已结束；
- 个人资料卡上的独立更多菜单；
- 页面内部筛选条件。

### 5.3 页面标题区

每个页面统一使用：

```text
页面标题          次要状态
一句话说明        [次操作] [主操作]
```

规则：

- 每页只有一个 `h1`。
- 一句话说明不超过 32 个汉字。
- 主操作最多一个；没有可执行动作时显示状态，不放禁用按钮墙。
- 保存状态只在发生变化时显示，稳定状态不持续抢占注意力。

### 5.4 全局活动抽屉

Agent 执行、Trace、运行耗时、工具错误和输出引用统一进入活动抽屉。

业务页面只展示与当前对象直接相关的最小状态，例如：

- “公司情报正在更新”；
- “回答已保存，等待 AI 评分”；
- “项目发生冲突，已停止覆盖”。

不在业务首屏展示完整执行时间线。

## 6. 页面 PRD

## 6.1 今日

### 页面职责

回答“现在最值得完成的一件事是什么”。

### 首屏结构

```text
┌ 今日 ──────────────────────────────┐
│ 当前最优先行动                      │
│ 完成 AI 应用工程 Base Resume        │
│ 原因：还没有可用于岗位定制的母版     │
│                         [继续完成]  │
├────────────────────────────────────┤
│ 今日待办：待筛选 3 · 待复习 2 · 待导出 1 │
├────────────────────────────────────┤
│ 最近变化                            │
└────────────────────────────────────┘
```

### 内容规则

- 最优先行动只显示一个，由现有流程状态确定性计算。
- 今日待办最多显示 3 项；每项直接进入目标对象。
- 最近变化最多显示 5 条，只展示用户能理解的业务变化。
- 不展示完整岗位列表、JD 收件箱、简历编辑器或题库。
- 数据源未初始化时，唯一主操作为“建立求职数据”。

### 验收标准

- 打开面板后无需滚动即可看到一个可执行主操作。
- 点击主操作最多一次跳转到真实工作位置。
- 首页没有任何大段说明、完整列表或配置表单。

## 6.2 岗位

### 页面职责

收集、筛选和推进岗位；所有围绕具体岗位的内容在同一上下文完成。

### 一级结构

岗位页顶部使用三个轻量切换项：

- 机会；
- JD 收件箱；
- 获取岗位。

默认进入“机会”。

### 机会视图

```text
┌ 筛选与搜索 ─────────────────────────┐
│ 阶段 / 来源 / 关键词 / 排序          │
├──────────────┬─────────────────────┤
│ 岗位列表      │ 当前岗位             │
│              │ JD | 情报 | 材料 | 进展 │
│              │                     │
└──────────────┴─────────────────────┘
```

#### 列表规则

- 卡片只显示公司、岗位、地点、薪资、阶段、完整度和一个风险提示。
- “感兴趣 / 忽略”只在待筛选岗位显示。
- 其他动作进入详情区，不在每张卡堆叠按钮。
- 待补全线索属于 JD 收件箱，不在岗位列表底部折叠展示。

#### 详情标签

1. **JD**：完整正文、来源、核验状态。
2. **公司情报**：官网事实、公开评价、面试情报、风险和来源。
3. **准备材料**：绑定的岗位版简历、面试题单、补强计划。
4. **投递进展**：阶段、下一步、提醒、备注和时间线。

“生成岗位版”“准备面试”“更新公司情报”等动作根据当前详情标签出现，不同时常驻。

### JD 收件箱

- 集中展示粘贴文字、截图、PDF、Word 和项目文件的识别状态。
- 首屏只有一个主操作“添加 JD”。
- 扫描项目收件箱作为次操作。
- 已成功转成正式岗位的来源默认折叠到“已处理”。
- 不重复显示“岗位从哪里进入池子”的三张说明卡。

### 获取岗位

- 第一步选择：招聘网站、手工导入、项目收件箱。
- 选择招聘网站后再展示渠道状态和搜索条件。
- Cookie 安全说明默认收起，只在登录动作附近展示。
- 定时补充完整 JD 放在“自动获取”折叠区，不与手工搜索并列为首要任务。

### 验收标准

- 阶段筛选只在岗位页出现一次。
- 从岗位列表打开 JD 不超过一次点击。
- 从具体岗位打开公司情报、岗位版简历和面试准备均不超过两次点击。
- 岗位页不出现全局 Agent 任务编排器。
- 没有选中岗位时，详情区给出唯一下一步，不展示空白仪表盘。

## 6.3 简历

### 页面职责

维护 Base Resume、岗位版和投递文件，并明确当前版本是否可投。

### 默认结构

```text
┌ 当前版本：AI 应用工程 Base ── [保存修改] ┐
│ 状态：3 项待核验 · PDF 已过期             │
├────────────┬─────────────────┬──────────┤
│ 版本选择    │ 简历正文         │ 上下文抽屉 │
│ Base        │ 预览 / 编辑      │ 默认关闭   │
│ 岗位版      │                 │            │
└────────────┴─────────────────┴──────────┘
```

### 页面分区

顶部只保留三个轻量入口：

- 内容；
- 版本；
- 投递文件。

#### 内容

- 中心区域只展示当前简历正文。
- 预览和编辑是同一位置的模式切换。
- 当前版本状态压缩为一行：版本类型、绑定岗位、核验状态、PDF 新鲜度。
- 主操作根据状态动态变化：生成 Base、保存修改、生成岗位版或导出 PDF。

#### 按需抽屉

以下内容默认不占据正文区域：

- 事实与证据；
- 私有事实 QA；
- Base → JD 差异；
- 样式、密度和照片；
- 生成 Trace。

抽屉入口显示数量，例如“证据 8/10”“待回答 3”，用户需要时再展开。

#### 版本

- 显示 Base → JD Variant 的来源关系，不和正文编辑同屏展开所有卡片。
- 默认按方向分组，再按更新时间排序。
- 恢复历史版本继续创建新 revision，不改变现有不可变规则。

#### 投递文件

- 只展示 PDF/Markdown 导出记录、新鲜度和对应版本。
- 主操作为“导出当前版本”。
- 内部证据账本作为关联文件展示，不混入公开简历预览。

### 验收标准

- 进入简历页立即看到当前简历正文，而不是先看到流程说明和版本卡片墙。
- 首屏只有一个主操作。
- 证据、事实 QA、样式和差异默认不同时展开。
- 从当前版本导出 PDF 不超过两次点击。
- 用户始终能看出当前编辑的是 Base 还是某个岗位版。

## 6.4 面试

### 页面职责

默认帮助用户立即开始练习；题库维护和历史分析是次级工作区。

### 一级切换

- 练习；
- 题库；
- 记录。

默认进入“练习”。

### 练习首页

```text
┌ 继续上次 / 今日推荐 ─────────────────┐
│ 继续 AI Agent 模拟 · 剩余 6 题 [继续] │
├─────────────────────────────────────┤
│ [练 1 题]  [10 分钟练习]  [完整模拟] │
├─────────────────────────────────────┤
│ 今日到期 2 题 · 最近薄弱：回答深度     │
└─────────────────────────────────────┘
```

规则：

- 有未完成场次时，“继续上次”是唯一主操作。
- 没有未完成场次时，“练 1 题”是默认主操作。
- 可练题不足时，只显示一个明确修复入口，不同时展示健康度、生成器和空题单。
- “单 JD / JD 聚合生成题单”移到“新建题单”弹窗。
- 训练洞察放到完成后的场次总结和“记录”中，不在练习前占据首屏。

### 专注答题

专注答题保持覆盖式大面板，每次只处理一道题：

1. 题目；
2. 回答提示；
3. 输入或语音；
4. 保存；
5. 可选 AI 评分；
6. 重练或下一题。

保存后必须原地明确显示：

- 回答已经写入当前项目；
- 评分是否已经完成；
- 优化稿如何使用；
- 下一题入口。

参考稿默认收起，评分和优化稿只在保存回答后出现。

### 题库

- 顶部保留搜索、状态、题型和排序，但统计卡从 6 张压缩为一行可点击状态标签。
- 每张题目卡只显示题干、能力、状态、最近练习和两个操作：练习、编辑。
- Source、答案要点、参考答案、追问、笔记和完整历史进入题目详情。
- “从当前 Session 整理”和“手工加题”进入统一的“添加题目”菜单。
- “新建题单”在题库页右上角，不在练习首页长期展示两个生成大卡片。

### 记录

记录页使用三个筛选：

- 模拟场次；
- 能力趋势；
- 真实面试。

补强计划归入能力趋势或具体岗位的“准备材料”，不再与当前题目列表并排出现。

### 验收标准

- 有可练题时，打开面试页一次点击即可开始单题练习。
- 完整模拟不超过两次点击。
- 练习首页首屏不出现题单生成、题库健康度、完整能力图表和真实复盘列表。
- 回答、保存、评分、优化和下一题的状态顺序明确，不能出现“回答保存了但不知道在哪里评分”。
- 编辑任意题目不超过两次点击。

## 6.5 数据

### 页面职责

维护可核验的个人事实，并处理项目文件和同步问题。

### 一级切换

- 个人档案；
- 经历与项目；
- 文件与同步。

### 首屏

- 只显示整体完整度、最重要的 1–3 个缺口和一个主操作。
- 已识别资料数量使用紧凑摘要，不用多张来源卡重复导航。

### 个人档案

- 姓名、目标角色、联系方式、求职方向、简介和照片。
- 编辑态与只读态明确区分。

### 经历与项目

- 工作经历、项目、Repo 和证据来源按对象分组。
- 默认显示摘要；选择一项后查看完整事实和证据。

### 文件与同步

- 当前项目路径；
- `job-hunt-panel.json` 和分片状态；
- `career-data/` 资料状态；
- 最近同步、冲突、未保存草稿和恢复状态；
- 初始化、重新扫描和清空数据等危险操作。

系统存储细节不再与个人资料同屏常驻。

### 验收标准

- 用户能在首屏看出还缺哪三项关键事实。
- 编辑个人档案不依赖 Session。
- 技术性的文件、分片和同步信息只在“文件与同步”出现。
- 危险操作与日常编辑明显分离。

## 7. 关键流程

### 7.1 首次使用

```text
今日：建立求职数据
→ 数据：确认个人档案与经历
→ 简历：生成 Base Resume
→ 岗位：导入或获取 JD
→ 岗位：筛选感兴趣职位
→ 简历：生成岗位版并导出
→ 面试：开始针对性练习
```

每一步完成后回到“今日”时，只推荐下一件事，不显示完整流程导航条。

### 7.2 围绕一个岗位准备

```text
岗位列表
→ 选择岗位
→ 阅读 JD
→ 标记感兴趣
→ 查看公司情报
→ 准备材料：岗位版简历 / 题单 / 补强计划
→ 更新投递进展
```

用户不需要在“岗位、公司情报、简历、面试”四个顶层页面之间反复寻找同一个岗位。

### 7.3 单题练习

```text
面试：练 1 题
→ 专注答题
→ 保存回答到项目
→ 可选 AI 评分并优化
→ 再答一次或下一题
```

### 7.4 编辑题目

```text
面试：题库
→ 搜索或筛选
→ 编辑
→ 保存到题库 / 保存并立即练习
```

两个保存动作必须继续保留清晰差异。

## 8. 内容与交互规则

### 8.1 主次操作

- 一个页面首屏最多一个实心主按钮。
- 同一区域最多两个次按钮，其余进入菜单。
- 主按钮文案使用明确动词，例如“继续练习”“保存修改”“导出当前版本”。
- 不使用“处理”“开始”“继续”等缺少对象的模糊文案。

### 8.2 渐进展示

默认收起：

- Source 明细；
- Trace 和 Agent Prompt；
- 长篇安全说明；
- 版本差异逐条解释；
- 完整练习历史；
- 低频配置；
- 项目存储技术信息。

默认展开：

- 当前任务需要的信息；
- 阻止用户继续的错误；
- 用户刚刚保存或评分得到的结果。

### 8.3 空状态

每个空状态只回答三件事：

1. 这里为什么是空的；
2. 用户可以得到什么；
3. 唯一下一步是什么。

禁止同时展示多个禁用按钮和大段流程解释。

### 8.4 保存状态

- 未保存：靠近编辑对象显示。
- 保存中：禁用会造成重复提交的动作。
- 已保存：短暂确认后恢复安静状态。
- 保存失败：保留输入，显示重试。
- 外部冲突：全局横幅阻止覆盖，并提供重新读取入口。

## 9. 响应式要求

| 宽度 | 布局 |
| --- | --- |
| ≥ 1100px | 列表 + 详情双栏，必要时打开右侧抽屉 |
| 720–1099px | 列表与详情切换显示，顶部保留返回上下文 |
| < 720px | 单列；筛选进入抽屉；主操作固定在安全底部区域 |

专注答题在所有宽度下都优先占据完整可用区域，不嵌在题单的小卡片中。

## 10. 数据与兼容性

v4 页面重构默认复用现有业务字段：

| 页面 | 主要数据 |
| --- | --- |
| 今日 | 各业务对象计数、选中对象和确定性下一步 |
| 岗位 | `jobs`、`jobLeads`、`jdIntakeItems`、`jobResearch`、投递阶段 |
| 简历 | `resume`、`versions`、`profile`、证据、QA 和导出记录 |
| 面试 | `questionBank`、`interviewSets`、`mockInterviewSessions`、`interviewDebriefs` |
| 数据 | `profile`、`experiences`、`repos`、项目同步状态 |

首版不要求改变 `job-hunt-panel.json` 的业务 schema。

仅新增小型 UI 状态：

- 当前顶层页面；
- 页面内标签；
- 抽屉开关；
- 筛选条件；
- 最近查看对象。

这些状态继续保存在 Panel 小型 storage，不进入业务主数据。

旧页面状态迁移：

| 旧页面 | 新位置 |
| --- | --- |
| `dashboard` | `jobs / opportunities` |
| `channels` | `jobs / acquisition` |
| `research` | `jobs / selected-job / intelligence` |
| `resumes` | `resume / content` |
| `interviews + practice` | `interview / practice` |
| `interviews + bank` | `interview / bank` |
| `materials` | `data / profile` |

## 11. 可访问性与键盘

- 页面切换后把焦点移动到新页面 `h1`。
- 列表进入详情后，窄屏提供明确返回按钮。
- Tab 只用于同一页面内同级内容，不用 Tab 隐藏顺序流程。
- 抽屉和弹窗必须支持 `Esc`、焦点循环和关闭后焦点恢复。
- 保存、录音、转写和评分状态使用可感知的 `aria-live`。
- 颜色不能作为阶段、分数或错误的唯一表达。

## 12. 成功指标

首版通过任务走查和回归测试验证，不依赖外部遥测。

### 效率指标

- 打开面板到进入当前优先任务：≤ 1 次点击。
- 开始单题练习：≤ 1 次点击。
- 开始完整模拟：≤ 2 次点击。
- 从岗位打开公司情报：≤ 2 次点击。
- 从当前简历导出 PDF：≤ 2 次点击。
- 在题库编辑一道题：≤ 2 次点击。

### 界面指标

- 顶层导航固定为 5 项。
- 业务页面首屏实心主按钮不超过 1 个。
- 页面首屏大型内容区不超过 3 个。
- 同一筛选条件只出现一次。
- 不在业务首屏常驻 Trace、完整 Source、项目分片或长篇安全说明。

### 可靠性指标

- 页面重构前后的业务对象数量一致。
- 现有简历版本、回答、评分、题单、JD 和投递时间线均可访问。
- 所有确定性编辑继续先写项目，失败时回滚或保留草稿。
- 外部更新和多窗口冲突保护不得降级。

## 13. 交付阶段

### Phase 1：外壳与路由

- 新增“今日”。
- 顶层导航收敛为 5 项。
- 移除侧栏岗位阶段筛选。
- Session / Trace 改为活动抽屉。
- 建立旧路由迁移。

### Phase 2：岗位工作台

- 合并岗位池、JD 收件箱、渠道和公司情报。
- 建立岗位详情四标签。
- 移除全局任务编排器常驻区。

### Phase 3：简历工作台

- 当前版本优先。
- 证据、QA、差异和样式改为按需抽屉。
- 版本库与投递文件独立视图。

### Phase 4：面试工作台

- 练习、题库、记录三分区。
- 练习首页只保留开练入口。
- 题单生成进入弹窗。
- 洞察、补强计划和复盘归入记录或岗位上下文。

### Phase 5：数据页与清理

- 个人档案、经历与项目、文件与同步三分区。
- 删除重复说明和旧容器样式。
- 完成窄屏、键盘和可访问性回归。

## 15. 已确定的产品决策

1. 面板内完成模拟面试与回答保存；Session 只用于明确发起的 AI 评分、生成和讨论。
2. 长期题库是题目主数据；题单只负责选题。
3. 公司情报属于岗位上下文，不再作为独立顶层产品。
4. 渠道属于“获取岗位”的方式，不再作为独立顶层产品。
5. 数据源是事实维护区，不承担岗位、简历和面试的日常操作。
6. 简历默认展示当前版本；证据和历史按需展开。
7. 面试默认展示练习入口；分析和管理退到次级视图。
8. 下一版先完成信息架构和交互原型，再进行完整视觉升级。
