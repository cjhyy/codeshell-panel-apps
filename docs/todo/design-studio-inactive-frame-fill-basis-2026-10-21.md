# Inactive native Frame Fill basis

This change reserves physical inside-stroke widths for a `layout:none` Frame or Component when it participates as a main-axis Fill item. The rectangle rule already did this. Stored padding on an inactive container remains ignored; no CSS padding floor or `strokeLayoutExcluded` applicability was added.

The native evidence is an owned Figma desktop 126.9.13 research run with 32 cases and no setter errors. The tracked fixture preserves unchanged official subtree objects and matching live case objects, each independently hashed. Its raw result SHA256 is `2ece3bfe65c19b266cf76d14aa6dc0861c3b113234a7cc08b0aa9e814ef46a7a`; official JSON SHA256 is `bfdf90aa2f3e4047c2c4ee83270452b5bbcd712605b47163320ece6c2f071143`. The raw evidence remains outside git under `evidence/inactive-frame-fill-analysis/native-inactive-frame-fill-2026-10-20T20-21-13.770Z-4221e005` in the aggregate task workspace.

For both parent axes, inactive Frames with retained raw padding 8/20 and inside strokes 4/8 have outer sizes 302/310 at 640, 182/190 at 400, 36/44 at 108 and 12/20 at 60. Padding-only controls instead divide equal outer sizes 306/306 at 640 and 186/186 at 400. Thus inactive padding contributes nothing, while the physical stroke basis is 8/16. Official REST omits those inactive padding fields even though the live SDK retains them. Component coverage is a canonical rectangular-container test; this run did not create a native Component.

The new native import preflight accepts only the measured two-leaf Fill pattern with positive remaining content, start alignment, no wrapping/rotation/negative gap, and matching main-axis sizes and positions. Mixed active/inactive containers, additional flow items, unsupported stroke conversion, content minima above stroke basis, below-basis maxima, and zero/exhausted remaining content retain measured parent geometry with the existing `native-stroke-fill-model` diagnostic. Rejection clears direct Fill/alignment relationships while preserving each nested child's own layout and stroke semantics. Existing active-container and Rectangle-only behavior is unchanged.

The preflight validates captured native inputs; it is not a claim about an unavailable native layout version or every later sizing edit. Native content-cap loss and arbitrary positive content minima still need their separately proposed sizing model. Fixed/cross-axis stroke floors, Grid/wrap/Text rules, and native leaf sizing below total stroke basis were not established by this evidence. No new provenance or policy field was introduced.
