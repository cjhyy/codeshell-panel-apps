# HTML number line-height preservation

The maintained capture boundary now records a real Element's Typed OM `line-height` number, with the computed font size used by its Text style. Matching finite numbers in the existing 0.7–3 range become ordinary canonical ratios without the adapter's two-decimal geometry rounding. The same capture-local decision survives the plain/pre/nowrap recovery pass. Save/reopen retains the scalar; no schema field, CSS execution or new native capability is added.

Source metadata is keyed by the original semantic object and attached only to its matching Text. Generated and first-line/first-letter typography variants, mixed runs, font mismatches, unavailable Typed OM and unsupported values retain the old fallback and diagnostics. Resolved lengths cannot distinguish direct px, percentages, em, inherited lengths or calculations from one computed value; they keep the existing fallback with an explicit `html-line-height-intent` warning. `normal` also stays a diagnosed fallback. This change does not convert resolved lengths to the new pixels unit.

Research and immutable CPU evidence are outside the checkout at `evidence/html-lineheight-intent-research` under the 24h goal worktree. Chromium ran with explicit `--disable-gpu`: 24 CSS forms across two 16→24→16 edit paths and four frozen GOV/Bootstrap documents at 1280/768/400/1280. Primary specifications: [Typed OM computed values](https://www.w3.org/TR/css-typed-om-1/#computed-stylepropertymapreadonly-objects), [CSS line-height computation and inheritance](https://www.w3.org/TR/CSS2/visudet.html#propdef-line-height).

Frozen GOV authors unitless `1.3157894737`; Chromium returns number `1.3157894897460938`, while legacy CSSOM reports 25px at font size 19. Before this change, 48 of 58 three-column Text nodes and 7 of 9 no-actions Text nodes become 1.32, an effective 25.08px. In the bounded candidate, 30 three-column and 8 no-actions Text nodes retain the actual computed number; unsupported/mixed sources stay diagnosed. Other font sizes, source characters and measured widths remain unchanged. Bootstrap's sampled 1/1.2/1.25/1.5 values are numbers; its viewport-dependent font sizes are a separate captured-state limitation.

The three-column native transfer still rejects the pre-existing negative-spacing relationship. Minimal number19 and number16 fixtures retain imported/relayout/narrow strict 0 before and after.

New tests cover exact numbers, inheritance, var/calc-number, pre/nowrap recovery, save/reopen, unavailable Typed OM and malformed/pseudo/mixed evidence. Same-font SVG source/reopen/narrow and a fresh font-size-24 capture, plus frontend 19→24→19 and width 400, compare every RGBA channel exactly.
