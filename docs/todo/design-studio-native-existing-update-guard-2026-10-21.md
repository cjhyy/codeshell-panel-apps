## Bounded new lane

An explicit private existing-update-only lane supports `notes`, `name`, `visible`, `locked`, `opacity`, opaque single SOLID `fill`, and plain Text characters/scalar typography. It also protects those supported ordinary no-notes updates. It does not infer eligibility from the wider `PATCH_KEYS` set. All operations must be updates; parent/page/order, geometry, image, layout, creation and deletion do not enter it. Complex paint/shadow stacks and non400/700 requested text weights remain outside this lane. Mixed notes with unsupported operations still refuse; ordinary legacy paths outside this scope are not claimed race-free.

`existing-update-runtime.mjs` privately brands the exact patch using a WeakMap. JSON metadata cannot grant eligibility. The notes capture accepts this brand only for the exact same patch and still requires the fresh same-plugin complete notes baseline. Unmapped descendant notes, source mapping, file/parent identity and every existing original nativeText range update/clear/delete refusal remain independent requirements. The12 existing text source/plan/capture/write modules remain byte-identical to126.

Exact native references, ancestry and ordered children are captured before the first own target REST await. The guard captures the complete required SDK projection, corroborates it against that node's own returned REST, and rechecks after asynchronous dependencies. Plain Text uses the existing complete catalog and uniform-only read proof; it never enables a range setter. Missing/mixed/throwing required scalar metrics, hidden links, style references, nonzero/unused override tables, unreviewed raw style keys, variables and unsupported paints refuse. The SDK's explicitly missing scalar fontStyle and raw hyperlink getter1 remain distinct observations under the existing codec rather than invented values.

All font awaits finish during preflight. After the caller returns from preflight, compile creates owned setter values and binds synchronous methods. Complete field/notes/topology checks run again before `commitUndo` and immediately afterward. The new commit has no async factory, lookup, export, font load or reconciliation. Text source metadata merges into the exact current `codeshellDesignMetadata` object, retaining unrelated keys. Unrelated plugin keys are not rewritten. Notes-only/deletion use the prior branch; a latest blue fill remains untouched by a notes-only update.

## Final readback and numeric limits

Before the final undo checkpoint/success response, synchronous readback verifies exact intended strings, booleans, notes, merged metadata and original identities/topology. Captured unrelated SDK fields and complete Text scalar/segment/getter values must remain unchanged except the prepared intents. Silent no-op character/name/visibility/notes/metadata/fontSize setters refuse and request undo.

Numeric values require exact returned equality. The only additional conversion is the already retained native PERCENT line-height contract from1ad67f0: exact unit plus `Math.fround(requested.value / 100) * 100`. There is no epsilon or general Float32 rule. Other native normalization, including fractional font-size or RGB rounding, is not qualified: differing readback refuses and requests undo. VM exact SOLID color success does not prove all native color transport. Actual Figma acceptance must determine additional safe contracts independently.

The guard bounds each complete observation/required REST projection to256KiB, initial observations to16MiB, repeated observations to64MiB, and repeated context checks to200000 references. Context retains bounded50000 children,100000 initial references,50036 nodes and depth35. Oversized coupled updates refuse rather than performing quadratic unbounded work. It reads only the complete required raw projection, preserving original raw source and unrelated subtrees.

A setter/undo failure preserves the original error and any failed checkpoint/undo request. Undo remains a request, not proof of complete rollback or preservation under arbitrary synchronous SDK reentrancy. No awaited staging interval is rolled back by this lane. Full-document/unknown REST-only atomic freshness, real native persistence/pixels, structural transactions and arbitrary concurrent reentrant SDK callbacks remain unproved.
