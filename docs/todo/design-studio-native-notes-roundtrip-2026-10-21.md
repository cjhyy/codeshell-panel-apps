## Data contract

`codeshell.figma.source`v1 gains optional independent `nativeNotes:{version:1,pluginId,nodes}`. Each keyed source ID has exactly `{type,notes}`. Notes are either `{kind:"value",value:<nonempty exact string>}` or `{kind:"absent"}`. Value is inert user metadata; its contents are never interpreted as text/layout/preview/native authorization. Unknown raw pluginData, shared data and foreign namespaces remain unconsumed. Raw official nodes, unknown fields and numbers are retained.

Missing table/entry is unknown, not observed absence. The explicit absent state means the own-plugin current SDK getter returned an empty string. The [Figma API](https://developers.figma.com/docs/plugins/api/properties/nodes-setplugindata/) deletes a key on empty-string write, while the [getter](https://developers.figma.com/docs/plugins/api/DocumentNode/) returns an empty string for missing data. Therefore this path does not claim lossless preservation of canonical `notes:""` versus absent notes, and introduces no presence carrier. Ordinary whitespace and Unicode strings remain exact.

The normalizer uses a descriptor-owned complete-envelope clone before serialization for this field, validates complete raw source overlap/content/location, and requires each metadata ID/type to match a real raw source node. If raw REST explicitly includes `pluginData[actualPluginId].codeshellNotes`, that value must agree with the independent observation. This is a consistency-only veto: missing keys, foreign/shared namespaces and arbitrary raw pluginData never supply notes or a baseline. Source binding and local canonical save/reopen retain the table. A preview fallback can carry its own root note; omitted descendants remain in the source record and are not presented as recovered canonical requirement coverage.

Keep canonical2000UTF16, complete source notes record16KiB, actual SDK pluginId/key/value100000byte and complete serialized16MiB envelope budgets. The separate patch baseline additionally limits ordered child links to50000 and validates every referenced descendant; the child-ID array is covered by the complete envelope cap rather than the16KiB source-record cap. The last cap includes raw nodes, notes, text sources/hints, assets, previews, selection and warnings. No truncation, fitting, rounding or per-node-only accounting makes an oversized envelope valid.

## Export and existing-node safety

The independent notes collector observes all exported nodes, including Page and unsupported/unmapped descendants. It reads only the actual own-plugin key, holds exact native references and cached ancestry/ordered child identities, and refuses unavailable getters, contradictory overlaps and stale metadata. After all awaited REST/image/PNG/SVG work, metadata/text finalize synchronously and notes/identity are rechecked before source serialization. Existing text catalogs, metric/preview admission, hint rules and original range update/clear/delete hard guards are unchanged. This observes current SDK fields anchored to prior own REST; it does not establish arbitrary REST-only or whole-document atomic freshness.

Existing-node notes replacement, empty/removed-property clear and deletion require a fresh matching notes baseline for every affected source descendant. `patch.nativeNotesBefore` is an independent expected-value projection derived from the saved complete official source; each entry adds ordered child IDs. Ordinary update `operation.before` deliberately omits descendants, so this extra catalog is necessary to protect unmapped grandchildren without rewriting raw before snapshots.

Notes-sensitive original-node patches currently accept only notes-only updates and deletions. Any mixed create/move/font/other asynchronous operation is explicitly refused before original writes. The writer captures exact targets before awaited REST reads, rechecks complete affected topology/metadata after the last preflight await, then enters a separate synchronous commit branch containing no factory/font/parent lookup/layout setter or await. File/mapping/parent identity, allowDeletes, source range boundaries and existing raw conflict checks remain required. Metadata never substitutes for those checks. Source-less legacy deletion is now blocked until a fresh complete snapshot is exported; mixed deletion remains blocked pending proven synchronous staging.
