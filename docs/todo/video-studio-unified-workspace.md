# 视频面板统一工作区方案

日期：2026-09-17；更新：2026-09-24。状态：0.6.7 完成第 1、2 步；0.7.0 完成第 3 步（字幕、粗剪、录制、口播、配音、AI、本人口播均直接写入 `EditorDocument`，不再经旧视图写回）。第 4 步清理双界面仅部分完成：桌面版不再使用旧预览/时间线，浏览器调试参数下的旧界面仍保留。

## 用户目标

1. 多轨时间线是整个视频面板的编辑底座，不是“素材”标签的专属页面。
2. 切换功能时，工程、素材、预览、时间线和选中状态保持在原位；变化集中在该功能的工具与属性。
3. 左侧素材库保持固定入口：可以常驻，也可以与当前功能工具一键切换；工作区其余部分不随之替换。0.6.7 采用一键切换，避免窄窗口挤压预览。
4. 各功能的产物进入同一份可继续编辑的工程。第三点的具体交互以用户补充为准。
5. 主要模块之间的分界线可拖动，用户可以自行分配素材、预览、属性和多轨时间线的空间。

## 当前结构与问题

`EditorDocument`（schema 2）已是权威工程，包含素材、序列、轨道、片段和制作注释。`EditorSession` 提供编辑事务与持久化。新版 `EditorWorkspace` 已有多轨时间线、预览和属性编辑；这部分底座可以复用。

界面却仍采用双层结构：`views.ts` 生成旧版完整页面（素材栏、预览、属性、旧时间线）；`main.ts` 只在 `tab === "media"` 时显示嵌入式 `EditorWorkspace`，并通过 CSS 隐藏旧版预览/时间线。切到粗剪、录制、口播、字幕、配音、AI 制作或任务时，旧版页面重新出现。功能内容还会替换左侧 `.library-panel`。导航处理会停止播放并清除素材预览状态；`render()` 会重新生成大部分页面。于是同一工程出现两种时间线外观、两套预览控件和明显的布局跳变。

旧功能通过 `projectLegacyView()` 从 schema 2 投影出 schema 1 的 `Project`。兼容层有意限制不能准确映射的多轨操作，但旧界面仍以这个投影视图呈现和操作。这使其他标签天然无法完整显示多轨序列；继续补旧时间线会扩大双轨架构的维护成本。

## 目标工作区

```text
固定顶栏：工程名 / 保存状态 / 撤销 / 导出
固定左导航：素材 / 粗剪 / 录制 / 口播 / 字幕 / 配音 / AI / 任务
固定素材库：导入、搜索、文件夹、拖入时间线；可折叠但不随功能卸载
中央：同一个多轨合成预览；进入原片粗剪时在这里切换预览模式
右侧：选中片段属性或当前功能参数；必要时打开功能抽屉/对话框
固定底部：同一个多轨时间线、播放头和缩放控制
```

切换导航只改变“正在使用的工具”，不改变工程编辑底座。功能可以增加自己的面板、浮层和工具栏按钮，不能建立另一套预览/时间线。任务列表可作为抽屉打开，运行中任务在顶栏显示精简状态；它不应让时间线消失。

### 可调整的模块尺寸

- 素材库与预览、预览与右侧属性区之间使用纵向拖拽分界线；预览与底部时间线之间使用横向拖拽分界线。若打开独立功能抽屉，它与相邻模块之间也有分界线。
- 拖动时实时改变布局，保留预览画面的正确比例；时间线轨道、播放头和水平滚动位置不重置。分界线应有明确的悬停/拖动反馈，并提供双击恢复默认尺寸。
- 为素材操作、画面预览、属性编辑和多轨操作分别设置最低可用尺寸；拖到边界时停住，不把模块挤成无法点击的细条。窄窗口先收起功能抽屉和属性区，再允许折叠素材库；折叠后始终有固定的展开入口。
- 尺寸属于本机工作区偏好，跨功能标签和面板重开保持；它不修改视频工程文档，也不随工程包传给其他设备。窗口变化时按可用空间约束已有尺寸，不覆盖用户保存的宽高偏好。
- 分界线支持键盘方向键调整和可访问名称。拖动只更新布局尺寸，不触发整页重渲染、重新加载媒体或重建播放任务。预览和时间线在尺寸稳定后按容器大小重绘。

`StudioShell` 负责以上固定区域及响应式布局。`EditorWorkspace` 负责唯一的预览、时间线和选中片段属性。`FeatureModule` 仅声明导航入口、工具面板、选区需求和功能动作，通过统一 `EditorContext` 读取当前序列、播放头、选中片段和素材，并用 `EditorSession` 的编辑事务提交结果。功能任务和媒体资源仍由现有面板 SDK/Host 授权接口处理；Host 不承载视频领域逻辑。

| 功能 | 固定工作区内的入口 | 写入同一工程的结果 |
| --- | --- | --- |
| 素材 | 常驻左侧素材库 | 素材引用，拖放后形成指定轨道上的片段 |
| 粗剪 | 原片预览模式 + 右侧保留范围 | 经审阅后在当前序列新增/裁剪片段 |
| 录制 | 录制对话框或抽屉 | 新素材；用户选择是否放入当前时间线位置 |
| 口播 / 配音 | 文案与声音工具面板 | 新声音素材及可编辑音轨片段；本人声音审批状态随工程保存 |
| 字幕 | 文稿面板 + 预览叠加层 | 当前序列的文字/字幕片段或绑定数据，点击句子定位播放头 |
| AI 制作 | 建议抽屉、差异预览和应用按钮 | 经版本校验的 `EditorOperation` 批次；保留撤销 |
| 任务 | 状态抽屉 + 顶栏进度 | 结果素材和导出记录，完成前不伪装成已应用的片段 |

## 状态与边界

- 工程数据：只写 `EditorDocument`；旧 `Project` 留作旧文件迁移及尚未改造流程的临时适配，不驱动第二套编辑界面。
- 工作区状态：活动功能、素材搜索/滚动、各模块尺寸、选区、播放头和原片预览模式属于同一会话。切换功能保留这些状态；模块尺寸另作为本机偏好持久保存。仅录制中未保存内容等真实冲突需要离开前处理。
- 功能结果：分析、转写和 AI 建议先作为待审结果显示；应用时以工程修订为前提，通过统一操作层一次提交。生成的媒体先登记为素材，再由明确的插入操作放进当前轨道。
- 轨道语义：每个功能对目标轨道类型和插入位置有明确规则；不能借用旧 `project.clips` 的单画面顺序来推断多轨位置。
- 播放：普通导航切换不停止预览，也不重新准备原片；只有切换工程、切换序列或进入独占的原片/录制模式时才做相应处理。

## 建议实施顺序

1. **固定工作区**：提取 `StudioShell`，让新版预览和多轨时间线在所有导航项下常驻；加入可拖动分界线和本机尺寸记忆，保留现有视觉样式，先消除切页跳变。
2. **固定素材库**：从“素材页内容”改为独立 `AssetDock`，常驻左侧并保存搜索、筛选、滚动和折叠状态；功能面板不再覆盖它。
3. **模块接入**：按字幕、粗剪、录制、配音/口播、AI、任务逐个将工具接入工作区，结果统一走 `EditorSession`；旧流程在转换前仍通过适配器保护工程。
4. **清理双界面**：确认每项功能在多轨工程上可用后，移除旧预览/时间线及其专属 CSS、重复播放状态和导航时的全页重渲染。

0.6.7 已完成固定工作区、左侧素材/工具切换和三条可拖动分界线。粗剪原片监看仍复用原有源预览，AI 建议仍显示在右侧原有审阅面板；这两处先保留以保障流程可用。浏览器调试可显式使用旧界面兼容参数，桌面安装默认进入统一工作区。后续将逐个把旧功能控制器接入统一的模块接口，再移除兼容视图。

## 验收场景

- 打开现有四轨工程，依次切换八个功能：预览、四轨时间线、素材库、播放头、选区和面板位置保持稳定。
- 拖动每条分界线并重开面板：尺寸保持；播放中的画面和声音不中断，时间线位置不跳动。拖到最小尺寸、缩窄窗口和双击复位时，各模块仍可操作。
- 从粗剪、录制、配音、字幕和 AI 产生结果，能在指定轨道看见并继续编辑；撤销后回到应用前状态。
- 播放中切换普通功能不重建预览任务；切换工程或进入录制时有明确、可恢复的状态处理。
- 旧工程迁移、现有多轨工程、素材重连与导出均仍从同一 `EditorDocument` 读取；不会产生两份不同的编辑结果。
