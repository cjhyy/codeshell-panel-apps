# Mimi Download 0.17.0：验收与演示

## 这一版的变化

- 下载页按“添加视频 → 下载设置 → 加入队列”组织。宽屏并列显示来源和设置，队列在右侧；窄屏可从顶部直接跳到队列。
- 下载环境默认折叠，保留醒目的版本状态。统一浅色、深色、空状态、错误提示和按钮层级。
- 多链接逐条显示标题与获取结果，支持取消获取、只重试失败项；失败时保留已成功的信息并留在当前页面。
- AI 找视频增加示例需求、步骤状态、查询记录筛选和“重新找视频”。外部 Provider、模型选择和聊天工具继续保留。
- 修复真实下载后的文件清单被误判为不完整的问题，使重复下载提醒依据实际文件生效，字幕也进入记录。

## 回归范围

自动化检查使用隔离的数据和 Host 模拟接口，涵盖多链接与播放列表、队列暂停/恢复/重试、取消信息获取、账号匹配与失效处理、字幕选项、不同 Provider、搜索结果与记录、目录记忆、真实文件检查接口和存储失败。界面检查覆盖 340、620、1280 像素及浅色/深色主题；截图中的示例标题属于测试数据。

本地真实流程另使用已安装的 yt-dlp、FFmpeg 和 FFprobe，以及自动生成的两秒测试视频。测试文件放在独立临时目录，不使用用户的视频或 Cookie。检查包括两条链接的信息获取和顺序下载、输出媒体流、重复提醒、删除文件后重下、MP3 转换、SRT 转换与嵌入、目录重开恢复、历史记录与文件校验。Host 授权和远端版本比较仍由测试接口提供，不把它当成真实登录验证。

在线来源抽查：YouTube 的“Blender tutorial”搜索返回了平台标题和视频链接。B站搜索返回了视频编号，但详情请求出现超时；外部平台可用性仍受网络和平台响应影响。此次没有重新登录用户账号，也没有声称所有外部 AI 服务都已在线成功调用。

### 重复提醒修复说明

旧代码在下载结束后读取 `__files_to_move`，实测返回 `NA`，即使视频已存在，也会把记录标成不完整。现在使用最终视频路径与保留下来的字幕路径，再由文件检查工具核对实际输出。[yt-dlp 的处理顺序](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/YoutubeDL.py)中，该内部字段会在 `after_move` 前被移除。

### 复跑

```sh
node --test tests/apps/video-download/*.test.mjs
node scripts/video-download-live-check.mjs --yt-dlp /absolute/path/to/yt-dlp --ffmpeg /absolute/path/to/ffmpeg
```

FFprobe 需与 FFmpeg 位于同一目录。真实流程报告和截图写入 `artifacts/video-download/live-pipeline/`；界面截图写入 `artifacts/video-download/interface/`。该脚本只访问自己生成的本地测试媒体，不下载第三方视频。

## 90 秒演示顺序

1. **0–10 秒**：展示新版下载页与右侧队列，说明“找到想看的，保存到本地”。
2. **10–25 秒**：粘贴两条已确认可访问的链接，获取信息，展示逐条标题。
3. **25–40 秒**：选择画质、字幕和保存位置，加入队列，切到任务页看进度。
4. **40–60 秒**：进入 AI 找视频，用具体主题搜索，展示平台来源标签，再把选中结果加入队列。
5. **60–75 秒**：展示下载记录，检查文件、定位视频，说明清除记录不会删除文件。
6. **75–90 秒**：回到查询记录，展示查看旧结果与重新搜索，再展示保存目录会记住。

录制前先用准备好的公开视频链接确认网络可用，下载过程可剪去等待时间。字幕展示用确实提供字幕的视频；登录页含账号信息时不纳入录屏。演示使用实际返回的结果，不使用回归截图中的模拟视频冒充线上来源。
